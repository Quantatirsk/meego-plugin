# 脚本模式

<!-- capability-metadata:start -->
## 平台能力标记

> 调用频次：无直接调用频次。本页用于平台说明、格式、目录或支持信息。

<!-- capability-metadata:end -->

脚本模式在插件前端运行短任务，适用于点击按钮后立即执行逻辑、不需要界面或仅在特定条件下打开界面的场景。这里的“后台”指前端界面背后的执行过程，不是持久运行的服务端任务。

该能力从按钮构成的“点击后效果”配置，原文说明适用于按钮构成的各场景。配套 [Script API](<../jssdk/Script.md#5068361e>) 明确 `getContext/end` 仅支持网页端，移动端不支持；不能把按钮点位支持移动端，推导为脚本执行生命周期也支持移动端。

**阅读导航**：[配置入口](#4ab9e040) · [执行限制](#b59ff70e) · [API 清单](#supported-api) · [结束脚本](#script-lifecycle)

## 配置入口

在开放平台添加或配置按钮构成时，将**点击后效果**设为**执行脚本**。按钮的展示位置与场景配置见官方[按钮 / Button](<../points/按钮 Button.md>)。

## 主入口的执行限制

| 限制 | 规则 |
| --- | --- |
| 最大执行时长 | **60 秒** |
| 相同脚本 | 不能同时执行 |
| 不同脚本 | 最多同时执行 **3 个** |
| 客户端 API | 只能使用下表列出的能力，不能直接套用自定义界面的全部 API |

原文未说明并发计数按用户、插件、页面还是其他维度隔离，也没有给出超出数量后的排队或拒绝机制，这些行为待核实。不要把“最多 3 个”解释为每个插件实例都能另行取得 3 个额度。

网页沙箱中，脚本模式还不允许表单提交、直接下载、指针锁定及地理位置访问，见[客户端开发限制](<客户端开发限制.md#mode-differences>)。单个客户端 API 的 20 QPS 限制也仍需遵守，与 60 秒脚本生命周期不是同一规则。

## 主入口支持的客户端 API

以下保留官方页面的完整支持清单。模块名后只允许列出的方法，不表示同模块其他方法全部可用。

| 类别 | 模块 | 支持的方法 |
| --- | --- | --- |
| 上下文 | `Context` | [load](<../jssdk/Context.md#f511e728>) |
| 上下文 | `Script` | 官方 [getContext](<../jssdk/Script.md#2d62241f>)、[end](<../jssdk/Script.md#c328a5d2>) |
| 通用能力 | `navigation` | [getHostname](<../jssdk/navigation.md#ad4e6303>)、[getHref](<../jssdk/navigation.md#e8e51eec>) |
| 通用能力 | `storage` | [setItem](<../jssdk/storage.md#760636ed>)、[getItem](<../jssdk/storage.md#d41b012e>)、[removeItem](<../jssdk/storage.md#34a7b298>)、[clear](<../jssdk/storage.md#9beaee03>) |
| 通用能力 | `clipboard` | 官方 [writeText](<../jssdk/clipboard.md#c0850036>) |
| 通用能力 | `modal` | 官方 [open](<../jssdk/modal.md#8ab02bbb>) |
| 通用能力 | `toast` | 官方 [info](<../jssdk/toast.md#cd989296>)、[warning](<../jssdk/toast.md#76cbcc9a>)、[error](<../jssdk/toast.md#0234f5c2>)、[success](<../jssdk/toast.md#c3a0fd93>)、[close](<../jssdk/toast.md#db4c1b1f>) |
| 通用能力 | `utils` | [getAuthCode](<../jssdk/utils.md#21b31584>) |
| 数据获取 | `Space` | 官方 [load](<../jssdk/Space.md#da8445aa>) |
| 数据获取 | `WorkObject` | 官方 [load](<../jssdk/WorkObject.md#d7653a20>) |
| 数据获取 | `WorkItem` | 官方 [load](<../jssdk/WorkItem.md#d92cb7a6>) |
| 数据获取 | `Field` | 官方 [load](<../jssdk/Field.md#5de03037>) |

需要注意的调用边界：

- 点位上下文通过 `window.JSSDK.script.getContext()` 获取，返回结构对应执行脚本时的按钮场景；字段含义见 [Button](<../jssdk/Button.md>)。主入口不要改用普通按钮弹窗的调用入口。
- `navigation.open`、`modal.confirm` 和 `Context.watch` 不在该主入口清单内，不能因为常规客户端文档提供这些方法就直接调用。
- 允许 `modal.open` 不等于允许任意弹窗行为。官方 [modal.open](<../jssdk/modal.md#8ab02bbb>) 另说明：脚本模式已有弹窗打开时，再次打开会被忽略并报错；脚本模式下没有普通 UI 模式的返回引用。
- 表中是客户端 JSSDK 能力，不是可申请的服务端 OpenAPI 权限列表。

<a id="script-lifecycle"></a>

## 完成后主动结束脚本

按照 [Script.end](<../jssdk/Script.md#c328a5d2>) 的定义，业务逻辑完成并不自动结束脚本的运行状态。应在需要完成的异步工作结束后，调用 `window.JSSDK.script.end()`；该调用会立即停止脚本并卸载执行容器。

下面仅展示获取上下文和统一结束的入口结构，不包含业务写操作。业务异步操作应在结束前完成，不能在 `script.end()` 之后继续安排必需逻辑。

```typescript
export default async function main(): Promise<void> {
  try {
    const context = await window.JSSDK.script.getContext();
    console.info({ spaceId: context.spaceId });
  } catch (error) {
    console.error('Script execution failed', error);
  } finally {
    void window.JSSDK.script.end();
  }
}
```

`end()` 的目的为停止容器，不应依赖它返回之后还能完成业务处理。打开交互界面时，应结合对应弹窗协议安排生命周期，不能直接照搬上述无交互短任务的结束时机。
