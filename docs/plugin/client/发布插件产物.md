## 产物限制

| 维度 | 上限 |
| --- | --- |
| 单个插件的产物总体积 | 50 MB |
| 单个 ResourceId 对应产物体积 | 8 MB |
| 合计文件数量 | 100 个 |

三项限制需要同时满足。原文未说明体积按压缩前还是压缩后统计，临界值应以实际上传校验为准。

需要引入更大资源时，原文建议自行提供资源存取服务，通过 JavaScript 动态加载。该方式用于调整资源交付方式，不改变平台上传限制。

## 构建并上传

在包含 `plugin.config.json` 的客户端工程根目录执行：

```sh
lpm release
```

开发工具按 `resources` 配置中的所有 `entry` 编译构建并上传。资源映射规则见[初始化插件工程](<初始化插件工程.md#table-content-1>)。

成功时终端输出产物版本编号，例如：

```text
[17:36:11] Build successfully!
Uploading bundles...
[17:36:12] Upload successfully! The latest version number is 1 .
```

其中 `1` 是本次上传产物的版本编号。记录实际输出，在后台创建插件版本时选择对应产物；不要把日志中的编号当作已发布的插件版本号。

### ResourceId 缺失

若当前工程没有覆盖后台构成所使用的 ResourceId，发布会中断，例如：

```text
[17:36:12][ERROR] The resource entries for these ids (page_web, page_mobile, button_web, button_mobile) are missing in plugin.config.json.
```

按日志列出的 ID 核对后台构成和本地 `resources`，补齐对应入口后重新构建上传。若因后台新增构成尚未同步，可在工程根目录使用初始化文档定义的 `lpm update` 同步，再检查生成的配置和代码。

日志里的四个 ID 是错误示例，不代表所有插件都必须配置这四种资源。是否缺失应以当前插件后台实际使用的资源为准。

## 选择产物版本并发布插件

依据[发布插件](<../guides/发布插件.md>)的后台流程：

1. 在“管理 > 插件发布”中创建版本。
2. 填写插件版本号、描述，并选择刚上传的产物版本。
3. 配置使用与可见范围，按企业插件或市场插件流程申请发布。
4. 已安装空间通过所选自动更新或管理员手动更新策略采用新版本。

| 名称 | 产生位置 | 用途 |
| --- | --- | --- |
| 产物版本 | 客户端构建上传后生成 | 标识一份已上传的客户端构建结果 |
| 插件版本号 | 开发者后台创建版本时填写 | 标识一次插件发布，关联选定的产物版本和发布配置 |

![后台创建和发布插件版本](<../assets/b6b69784a00b485aa0e47dfd.png>)

企业与市场插件的审核、可见范围、安装和更新操作以[发布插件官方指南](<../guides/发布插件.md>)为准，本篇只展开客户端产物上传链路。

## 仓库对应与校订

- [官方原文](https://project.feishu.cn/b/helpcenter/1p8d7djs/2akj6c1q)；。
- 产物版本和插件版本的区分依据发布指南中“创建版本时选择产物版本”的规则，避免把上传日志误读为已经发布。
- 仓库 `apps/authorization/package.json`、`apps/oa_push/package.json` 的 `build:local` 使用 `lpm release`；`build:prod` 则使用 `lpm build --zip` 和仓库自己的后续脚本。后者属于本地交付流程，不能仅凭脚本名称认为已完成开放平台发布。
- 保留完整限额和缺失资源日志，将错误日志改为文本围栏。本文整理未触发真实构建、上传或发布。
