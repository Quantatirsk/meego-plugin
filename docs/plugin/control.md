# Control 点位

Control 让插件在工作项详情表单、节点表单或表格列中提供自定义界面。平台不保存控件自身的值；控件的数据模型、存储位置和访问控制由插件实现。

## 平台事实

| 使用位置 | 网页端 | 移动端 | 平台渲染方式 |
| --- | --- | --- | --- |
| 详情页表单、节点表单 | 支持 | V7.36.0+ | 加载插件资源并由插件渲染 |
| 表格列 | 支持 | 不支持 | 由展示态布局和展示态数据接口驱动 |

Control 构成关联各端的 `resourceId`。表单控件在网页端滚动进入可视区域时才加载，因此页面打开并不等同于控件已经初始化。

表格列不是客户端控件的运行容器。平台请求展示态数据并渲染已配置布局；只有展示态数据返回 `editable: true` 且该控件同时实现表单场景时，编辑操作才会打开控件界面。

## 表单上下文

在表单控件中调用 [`window.JSSDK.control.getContext()`](control-get-context.md) 读取当前场景。识别顺序应先检查 `nodeId`，再检查 `workItemId`：节点表单通常也有工作项 ID。

| 场景 | 可用的稳定关联信息 |
| --- | --- |
| 节点表单 | `workItemId` 与 `nodeId` |
| 已创建工作项的详情表单 | `workItemId` |
| 新建工作项表单 | 临时 `UUID` |

当构成在新建页可见时，平台要求配置新建成功回调地址和 token。回调的请求、验签和响应契约不在本页复制；使用[Control 新建成功回调](../events/control-create-callback.md)作为该事件的唯一资料来源。

## 实施建议

- 将控件业务值和跨用户访问规则放在插件自己的数据边界中；不要把客户端加载时机当作数据已保存的信号。
- 新建页只把 `UUID` 当作创建前的临时关联键。收到并验证回调后，再建立与工作项 ID 的关联。
- 为网页端和移动端资源分别实现并测试入口；不要从一个端的可用性推导另一个端的组件能力。
- 表格列只返回布局已声明的数据类型，不向布局引擎传入未定义的复杂对象。

本页的建议不是平台配置 JSON 或回调 wire schema。
