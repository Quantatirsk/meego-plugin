# 飞书项目开发工具 CLI 介绍

飞书项目开发工具 CLI 是面向 AI Agent 的插件开发工具。它提供工程创建、配置管理、本地调试、构建和发布能力，并附带供 AI 开发工具使用的 Skills，使自然语言需求能够进入相应工程流程。

本篇依据 2026-07-08 官方说明整理，不是逐命令参数手册。命令选项和登录行为应与实际安装版本对应；案例见[CLI 开发实践](<飞书项目开发工具 CLI 开发实践.md>)。

<a id="46ad5f8f"></a>

## 工具定位

CLI 管理的是插件工程、插件或 AI 应用配置及其发布生命周期。它可以整理调用业务 OpenAPI 所需的权限和协议，但这些动作不等于执行工作项、视图或其他业务数据操作。

官方说明安装时会把配套 Skills 注册到本地 AI 工具，如 Trae、Claude Code、Gemini、Copilot、Codex。实际是否注册成功以安装输出和对应工具加载结果为准，不仅检查 `lpm` 命令是否存在。

<a id="00f1a9dc"></a>

## 核心能力

| 能力 | 主要结果 |
| --- | --- |
| 工程流程 | 从空目录创建工程，根据目标点位生成需要的前端代码 |
| 增量配置 | 读取远端现状并比较差异，再修改点位和基本信息 |
| 权限与协议梳理 | 输出 OpenAPI 权限缺口、Webhook 数据结构和后端对接说明 |
| 变更确认 | 对远端写入、删除和发布展示差异，并按官方流程取得确认 |

原文的“自动化”是对工程流程的描述，不是免除开发验证或保证生成代码正确。

<a id="b305b64f"></a>

## 安装与登录

### 安装 CLI

```sh
npm install --global @lark-project/cli@latest
```

安装完成后重新加载 AI 工具，使其读取新 Skills。若自动注册失败，根据 `stderr` 给出的实际 CLI 安装路径补装；下面的路径是占位示意。

```sh
npx skills add "/absolute/path/to/cli/skills" -g --all
```

该命令会安装 Skills 到本地 AI 工具环境，不能把项目目录当作 CLI 安装目录。原 shell 示例中的 `//` 注释已移除。

### 登录目标站点

```sh
lpm login --site-domain https://project.feishu.cn
```

按浏览器提示完成 OAuth 授权。私有化或其他站点使用实际站点域名，不能复用示例站点的身份配置。

<a id="2c27bdc3"></a>

### 接入文档检索

官方建议配置[文档检索 MCP](https://project.feishu.cn/b/helpcenter/1p8d7djs/y5y1ko4o)，供 AI 查询 SDK、字段定义和 OpenAPI 规范。知识检索没有获得依据时，不应推断或编造接口字段；本地文档也需要核对版本。

## 官方工作流中的确认机制

“看一下”“设计一下”“给个方案”等请求属于查看与规划。真实配置写入、权限申请和发布应按官方工作流展示变更并确认；本节记录该工作流要求，不将它推断为任意版本、任意独立 CLI 子命令都具备相同交互实现。

| 环节 | 触发条件 | 核对内容 |
| --- | --- | --- |
| 远端写入前 Diff | 点位、基本信息或权限变更 | 新增与修改字段、删除项、新增权限是否符合目标 |
| 删除确认 | 删除点位、属性、事件或字段配置 | 完整删除清单、实际依赖、是否把改名误识别为删除再新增 |
| 发布确认 | 发布线上插件版本 | 插件身份、配置一致性、构建结果和未处理的删除或权限变化 |

官方特别要求删除清单单独确认，发布前再次确认。涉及已有线上依赖时，是否需兼容、逐步发布或通知，应依据该插件实际使用情况判断。

<a id="7d98459a"></a>

## 技术边界

- **远端产物不是源码备份**：不能从已发布产物反向恢复完整客户端源码，修改已有功能需要原代码仓库。
- **接口信息需要依据**：配套文档检索和已知类型用于补充上下文，工具不能仅凭需求自动确定所有字段与协议。
- **后端部署独立**：CLI 可整理协议和权限，不提供自建后端的自动部署能力。
- **确认环节属于流程约束**：官方不提供通过参数跳过其发布、删除、权限变更确认环节的使用方式；具体流程按所安装的配套工具执行。

## 典型需求

以下提示词是需求示例，不是当前会话的执行指令。

<a id="c5b1dbc5"></a>

### 从零创建插件

> 在当前目录做一个飞书项目插件：在需求详情页加一个“从 Jira 导入”按钮，输入 ticket 号后把标题、描述和优先级同步到当前需求。

流程从工程脚手架开始，再判断点位、客户端代码、自建后端与 OpenAPI 权限需求。跨系统读取和工作项写回分别梳理。

<a id="a56809e0"></a>

### 新增或修改点位

> 在当前插件里新增一个 AI 字段，名称为“需求拆解建议”，配置输入项和写回方式。

先读取本地与远端配置，按增量草稿修改，再展示 Diff。应明确“新增”还是“修改已有点位”，避免覆盖已有同类功能。

<a id="2e5cf9a2"></a>

### 开发界面

> 给插件加一个详情页 Tab，显示当前需求的负责人、优先级和创建时间，并提供刷新按钮。

先配置点位，再生成 React 界面和 `window.JSSDK` 上下文读取代码。涉及写回数据或 Webhook 时，另行整理后端交接；仅生成界面不代表后端已实现。

<a id="6ab52ece"></a>

### 更新基本信息

> 把插件名称改成“需求同步助手”，选择效率工具分类，补充中英文描述，并更新图标。

提取名称、描述、分类、图标与可见范围等变更，展示实际配置差异后再更新远端。

<a id="94991ba5"></a>

### 整理后端对接

> AI 节点收到执行事件后调用后端拆分需求，再写回子需求列表。整理后端对接文档和所需权限。

输出 Webhook 输入、业务接口契约、OpenAPI 清单及权限要求，供后端开发者继续实现。交接文档不等同于已运行的服务。

<a id="e6dc0eef"></a>

### 检查权限缺口

> 插件需要读取工作项字段、创建子需求和追加评论。分析需要哪些 OpenAPI 权限，并检查当前缺什么。

比较业务需求与已有授权，先列缺口；真实权限申请与只读分析分开处理。

<a id="f9d3402b"></a>

### 启动和排错

> 当前插件启动报 Module not found，检查原因并修复。

在实际源码工程中调用对应工具链，结合终端日志定位依赖、配置或构建问题，见[开发调试咨询](<../guides/开发调试咨询.md>)。

<a id="62381518"></a>

### 发布插件

> 准备发布当前插件，先展示本地与远端的差异。

核对身份、配置一致性、删除与权限变化，完成构建检查，再按发布流程操作。产物上传与插件版本发布见[发布插件](<../guides/发布插件.md>)。
