# 兼容性说明与验签说明

事件回调接入需要分别处理两件事：事件结构增加字段时保持兼容，以及使用回调 token 校验请求签名。回调接收地址还必须能够从公网访问。

<a id="0f0ed051"></a>

## 事件结构的兼容规则

平台可能在回调顶层或 `data` 中增加字段。消费方应忽略未识别的扩展字段，避免因为新增字段而拒绝整个事件。

```json
{
  "data": {}
}
```

上面的对象仅表示外层结构，不是某个具体事件的完整请求。实际业务字段由对应事件定义：

| 变化 | 消费方处理方式 |
| --- | --- |
| 增加不认识的字段 | 忽略该字段，继续处理已知字段 |
| 可缺省字段没有传入 | 按业务语义设置合理默认值 |
| 处理所必需的字段缺失 | 仍需按对应事件定义校验，不能将“设置默认值”理解为所有缺失数据都有效 |

前两项是原文的兼容建议；第三项用于明确其适用边界，原文没有为所有字段统一定义默认值。

## 签名计算规则

在开放平台的“插件构成 → 监听事件”配置中查看回调 token。该值用于回调签名，不能与 `plugin_secret` 或 OpenAPI 访问凭证混用。

签名计算顺序如下：

1. 将当前插件的 `plugin_id`、请求体中的 `request_time` 和配置的回调 token 转为用于计算的字符串。
2. 按上述顺序直接拼接，不添加分隔符。
3. 对拼接结果的 UTF-8 字节计算 SHA-256。
4. 将结果转为小写十六进制字符串，与请求体中的 `signature` 比较。

```text
SHA256_UTF8(plugin_id + request_time + callback_token)
```

`request_time` 应使用请求中的原始时间值，不换算单位、不替换成本地时间。UTF-8 和十六进制表示与原文 Python 示例一致；三个语言示例在这里采用相同规则。

<a id="b91839a0"></a>

## 语言示例

### Go

```go
package callback

import (
    "crypto/sha256"
    "encoding/hex"
)

func CalculateSignature(pluginID, requestTime, callbackToken string) string {
    digest := sha256.Sum256([]byte(pluginID + requestTime + callbackToken))
    return hex.EncodeToString(digest[:])
}
```

原文使用 `strings.Builder`，却没有导入 `strings`。这里直接拼接三个字符串，保持相同输入字节和算法。

### Python

```python
import hashlib
import hmac


def calculate_signature(
    plugin_id: str, request_time: str, callback_token: str
) -> str:
    payload = f"{plugin_id}{request_time}{callback_token}".encode("utf-8")
    return hashlib.sha256(payload).hexdigest()


def verify_signature(
    plugin_id: str,
    request_time: str,
    callback_token: str,
    signature: str,
) -> bool:
    expected = calculate_signature(plugin_id, request_time, callback_token)
    return hmac.compare_digest(expected, signature)


assert calculate_signature(
    "MII_example", "1730184005453", "callback-token"
) == "b8824f0304aa9f1c90f5624315ac296aafc4e66b77b8f55fabbce22d40421ce0"
```

函数输入使用字符串；若解析后的 `request_time` 是整数，调用时使用它的十进制字符串表示。示例中的比较方式是本地补充，签名计算仍使用 SHA-256，并未改成 HMAC 算法。

### Java

```java
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;

public final class CallbackSignature {
    public static String calculateSignature(
        String pluginId, String requestTime, String callbackToken
    ) throws NoSuchAlgorithmException {
        byte[] payload = (pluginId + requestTime + callbackToken)
            .getBytes(StandardCharsets.UTF_8);
        byte[] digest = MessageDigest.getInstance("SHA-256").digest(payload);
        StringBuilder hex = new StringBuilder(digest.length * 2);
        for (byte value : digest) {
            int unsigned = value & 0xff;
            hex.append(Character.forDigit(unsigned >>> 4, 16));
            hex.append(Character.forDigit(unsigned & 0x0f, 16));
        }
        return hex.toString();
    }
}
```

原文 Java 示例依赖 Apache Commons Codec 的 `Hex`，且未显式指定字符集。这里使用 JDK 自带能力输出十六进制，并明确使用 UTF-8；不增加第三方依赖，兼容 Java 8。
