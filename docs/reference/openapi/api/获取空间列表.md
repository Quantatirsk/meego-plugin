# 获取空间列表

返回指定用户可访问、同时已安装当前插件的空间 ID 列表。结果是两个范围的交集，不等于该用户能访问的全部空间。接口权限位于[权限管理](../guides/权限管理.md)的“空间”分类。

## 使用结果

请求体必须提供目标用户的 `user_key`。成功响应的 `data` 是 `project_key` 字符串数组，不包含空间名称或管理员；需要这些属性时，将 ID 传给[获取空间详情](获取空间详情.md)。

排序只支持最近访问时间 `last_visited`：无前缀或 `+` 为升序，`-` 为降序。需要把最近访问的空间放在前面时，传入 `order: ["-last_visited"]`。

<a id="注意事项"></a>

## 注意事项

使用虚拟 Token 获取空间列表时，只能查询该插件在**权限管理 \> 选择数据范围**中设置的空间的数据。若想查询其他空间请使用正式 Token。

<a id="请求说明"></a>

## 请求说明

**请求方式**：`POST`

**请求地址**：`/open_api/projects`

<a id="请求参数"></a>

## 请求参数

<a id="header"></a>

### 请求头

接口调用的 Header 配置详见 [Header](../guides/OpenAPI概述.md#a8e43b86)。

<a id="Body"></a>

### 请求体

| 参数       | 类型           | 是否必须 | 说明                                                                     |
| ---------- | -------------- | -------- | ------------------------------------------------------------------------ |
| `user_key` | `string`       | 必须     | 指定用户的唯一标识，用于查询该用户的相关信息。 [详细说明](#field-note-1) |
| `order`    | `list<string>` | 可选     | [详细说明](#field-note-2)                                                |

<a id="field-note-1"></a>

**user_key**

指定用户的唯一标识，用于查询该用户的相关信息。

- 开发者自己的 user_key，在飞书项目空间左下角双击个人头像获取。
- 租户内其他成员的 user_key，请通过[搜索租户内的用户列表](搜索租户内的用户列表.md)接口获取。

<a id="field-note-2"></a>

**order**

排序字段，格式为前缀＋排序字段。＋号表示升序；-表示降序；不加默认为升序，目前仅支持对 `last_visited`（最近访问时间）排序。

示例：

- `last_visited` 表示按最近访问时间升序。
- `+last_visited` 表示按最近访问时间升序。
- `-last_visited` 表示按最近访问时间降序。

<a id="返回参数"></a>

## 返回参数

| 参数       | 类型           | 说明                                             |
| ---------- | -------------- | ------------------------------------------------ |
| `data`     | `list<string>` | 符合条件的空间 project_key 列表。                |
| `err`      | `object`       | 请求成功时返回空值，请求失败时返回实际错误信息。 |
| `err_msg`  | `string`       | 请求成功时返回空值，请求失败返回报错信息。       |
| `err_code` | `int32`        | 请求成功时返回0，请求失败返回实际错误码。        |

### `err`

| 参数     | 类型     | 说明                                                                                                                                                                             |
| -------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `code`   | `int32`  | In some scenarios, display the error codes corresponding to more detailed errors.                                                                                                |
| `msg`    | `string` | In some scenarios, more detailed error descriptions are displayed.                                                                                                               |
| `log_id` | `string` | The call chain identifier in the error reporting scenario is used to track the complete call chain when an error occurs, facilitating log recording and problem troubleshooting. |

<a id="请求示例"></a>

## 请求示例

### 默认排序

```json
{
  "user_key": "749112601802809****"
}
```

### 降序排列

```json
{
  "user_key": "749112601802809****",
  "order": ["-last_visited"]
}
```

<a id="返回示例"></a>

## 返回示例

### 默认排序

```json
{
  "err": {},
  "err_code": 0,
  "err_msg": "",
  "data": ["68ee2ffacb1d2aad2019****", "68ee1d78cb1d2aad2019****", "68382b399de4b0ec6c5a****"]
}
```

### 降序排列

```json
{
  "err": {},
  "err_code": 0,
  "err_msg": "",
  "data": ["68382b399de4b0ec6c5a****", "68ee1d78cb1d2aad2019****", "68ee2ffacb1d2aad2019****"]
}
```

### 查询结果为空

`err_code: 0` 且 `data: []` 表示本次未返回空间。按原文说明，应依次核对用户可访问空间与插件安装空间是否有交集、插件是否开通本接口授权；使用虚拟凭证时还需核对开发数据范围。

```json
{
  "err": {},
  "err_code": 0,
  "err_msg": "",
  "data": []
}
```

### 调用失败

以下示例中，由于 `user_key` 填写错误，因此返回错误码 30006，用户查询为空，需要更正 `user_key` 后重新调用。

```json
{
  "err_code": 30006,
  "err_msg": "User Not Found",
  "err": {
    "code": 30006,
    "msg": "User Not Found, please refer to https://project.feishu.cn/b/helpcenter/1p8d7djs/5aueo3jr",
    "log_id": "202510142000537C03753BB1E3984C****"
  }
}
```
