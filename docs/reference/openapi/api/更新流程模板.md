# 更新流程模板

使用节点或状态级 `action` 修改指定流程模板。节点流通过 `workflow_confs` 提交节点和完成任务的操作，状态流通过 `state_flow_confs` 提交状态操作。

## 使用前确认

| 操作对象 | 新增 | 删除 | 修改 |
| --- | --- | --- | --- |
| 节点 `workflow_confs` | `action=1` | `action=2`，用 `state_key` 定位 | `action=3` |
| 完成任务 `task_confs` | `action=1` | `action=2`，用任务 `id` 定位 | `action=3` |
| 状态 `state_flow_confs` | `action=1` | `action=2` | `action=3` |

调用身份需要空间配置权限。先读取模板详情取得节点、状态、前序节点和角色 ID；本篇表中必填的节点/状态 `state_key` 应逐项提供。

节点 `pass_mode` 为自动完成、单人确认、多人确认；完成任务的同名参数为人工确认、自动完成，不能共用一套枚举。

对应的平台功能介绍详见[节点流程规则配置](https://project.feishu.cn/1ykiuvvj/3bv61iew)或[状态流程配置](https://project.feishu.cn/1ykiuvvj/2lgf2cd8)，对应的权限申请在 权限管理-流程类型 分类下，相关功能介绍详见 [权限管理](../guides/权限管理.md)。

## 请求说明

- 请求方式：PUT

- 请求地址：/open_api/template/v2/update_template

<a id="请求参数"></a>

## 请求参数

<a id="header"></a>

### Header

接口调用的 Header 配置详见 [Header](../guides/OpenAPI概述.md#a8e43b86)。

<a id="Body"></a>

### Body

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `project_key` | string | 必须 | [说明](#parameter-note-1) |
| `template_id` | int64 | 必须 | [说明](#parameter-note-2) |
| `workflow_confs` | `list<object>` | 可选 | 节点流配置，参见[WorkflowConf](../formats/数据结构汇总.md#5d317343)结构规范。 |
| `state_flow_confs` | `list<object>` | 可选 | 状态流配置，遵循[StateFlowConf](../formats/数据结构汇总.md#64916340)结构规范。 |

<a id="parameter-note-1"></a>

**project_key：说明**

空间 ID（project_key），或者空间域名（simple_name）。
- 空间 ID（project_key），在飞书项目空间双击空间名称获取。
- 空间域名（simple_name），`simple_name` 一般在飞书项目空间 URL 中获取。例如空间 URL 为 “https://project.feishu.cn/doc/overview”，则 `simple_name`为 “doc”。

<a id="parameter-note-2"></a>

**template_id：说明**

模板 ID，必须显式填写。可以从以下途径获取：

- [获取创建工作项元数据](获取创建工作项元数据.md)接口中的 `template` 字段的 `options` 中获取，选择对应的 `value`。
- [获取工作项下的流程模板列表](获取工作项下的流程模板列表.md)接口的 `template_id`。
- [获取字段信息](获取字段信息.md)接口中的 `template` 字段的 `options` 中获取，选择对应的 `value`。

#### `workflow_confs` 的字段

| `different_schedule` | boolean | 可选 | 标识当节点负责人为多人时，是否默认开启差异化排期。支持的取值如下所示。<br>- `true`：需要差异化排期；<br>- `false`：不需要差异化排期。 |
| `visibility_usage_mode` | int64 | 可选 | 节点的可见性模式，用于控制节点在工作流中的显示条件。支持的取值如下所示。<br>- `1`：默认可见；<br>- `2`：条件可见（具体条件需在空间配置中查看）。 |
| `completion_tips` | string | 可选 | 节点完成提示 |
| `deletable` | boolean | 可选 | 是否允许删除节点 |
| `deletable_operation_role` | `list<string>` | 可选 | 删除操作授权角色 |
| `pass_mode` | int64 | 可选 | 节点的完成方式，用于控制节点在工作流中的完成确认机制。支持的取值如下所示。<br>- `1`：自动完成；<br>- `2`：单人确认；<br>- `3`：多人确认。 |
| `is_limit_node` | boolean | 可选 | 是否为限制节点 |
| `done_operation_role` | `list<string>` | 可选 | 完成操作授权角色 |
| `done_schedule` | boolean | 可选 | 节点流转估分排期是否必填 |
| `done_allocate_owner` | boolean | 可选 | 节点流转负责人是否必填 |
| `task_confs` | `list<object>` | 可选 | 完成任务，遵循[TaskConf](../formats/数据结构汇总.md#1da29d93)结构规范 |

<a id="parameter-note-3"></a>

**action：说明**

节点操作类型，用于标识对节点的操作行为。支持的取值如下所示。
- `1`：新增节点；
- `2`：删除节点（仅需传入 `state_key`）；
- `3`：修改节点。

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `action` | int64 | 可选 | 任务操作类型，用于标识对任务的操作行为。支持的取值如下所示。<br>- `1`：新增任务；<br>- `2`：删除任务（仅需传入任务 ID）；<br>- `3`：修改任务。 |
| `name` | string | 可选 | 任务名称 |
| `id` | string | 可选 | 任务 ID |
| `deliverable_field_id` | string | 可选 | 交付物字段 ID |
| `pass_mode` | int64 | 可选 | 任务的完成方式，用于控制任务在工作流中的完成确认机制。支持的取值如下所示。<br>- `1`：人工确认完成；<br>- `2`：自动完成。 |
| `node_pass_required_mode` | int64 | 可选 | 标识任务是否作为节点完成的必要条件。支持的取值如下所示。<br>- `1`：是；<br>- `2`：否。 |

| 参数 | 类型 | 是否必须 | 说明 |

| `authorized_roles` | `list<string>` | 可选 | 状态授权角色 key，可通过[获取流程角色配置详情](获取流程角色配置详情.md)接口获取，即返回值中 `id` 字段值。也可以在**空间配置\>工作项管理\>角色管理**页面查看**角色 ID**。 |
| `action` | int64 | 必须 | 状态操作类型，支持以下类型<br>- `1`：添加；<br>- `2`：删除；<br>- `3`：修改。 |

## 返回参数

| 参数 | 类型 | 说明 |
