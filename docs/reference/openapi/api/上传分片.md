# 上传分片

<a id="bc099a5f"></a>

向已经初始化的上传任务提交一个分片。失败的分片可以重试；所有需要的分片上传成功后，再调用[完成分片上传](完成分片上传.md)。权限见[权限管理](../guides/权限管理.md)中的“工作项实例”。

## 分片定位与校验

使用[分片初始化](分片初始化.md)得到的 `resource_id` 和 `multipart.need` 分片序号。序号从 **0** 开始，`md5` 是本次分片的内容摘要，不是整个文件的摘要，也不是初始化时生成资源 ID 的计算结果。

<a id="b8fc8621"></a>

## 请求定义

**请求方式**：`POST`
**请求地址**：`/open_api/:project_key/file/stream/upload/multipart/:resource_id/:part_number`

鉴权请求头见[OpenAPI 概述](../guides/OpenAPI概述.md#a8e43b86)。

### 路径参数

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_key` | `string` | 是 | 空间 key |
| `resource_id` | `string` | 是 | 与初始化任务一致的资源 ID |
| `part_number` | `int` | 是 | 从 `0` 开始的分片编号 |

### 查询参数与请求体

| 位置 | 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| Query | `md5` | `string` | 是 | 当前分片的 MD5 |
| Body | 无字段名 | 文件二进制 | 是 | 原始分片内容；请求体中不能再混入其他参数 |

该接口的 Body 是原始二进制流，不是 multipart 表单，也不是 JSON。下方是依据原文参数整理的调用写法，`part.bin` 表示已经按初始化返回大小切分出的单片文件：

```bash
curl --request POST "https://project.feishu.cn/open_api/${PROJECT_KEY}/file/stream/upload/multipart/${RESOURCE_ID}/${PART_NUMBER}?md5=${PART_MD5}" \
  --header "X-Plugin-Token: ${PLUGIN_ACCESS_TOKEN}" \
  --header "X-User-Key: ${USER_KEY}" \
  --header 'Content-Type: application/octet-stream' \
  --data-binary '@part.bin'
```

## 响应结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `int` | `0` 为成功，非零为实际错误码 |
| `message` | `string` | 响应信息，成功判定以 `code = 0` 为准 |
| `data` | `object` | 没有额外业务数据，示例返回 `null` |

原表未将上述字段标为必填。分片是否成功以 `code` 判断，不以 `data` 是否为空判断。

```json
{
  "code": 0,
  "message": "success",
  "data": null
}
```

<a id="ddae73a7"></a>

## 错误码

原表沿用 `err_code` 等表头，本接口实际响应为 `code/message`。通用说明见[Open API 错误码](../formats/Open%20API%20错误码.md)。

| 编号 | 原错误名称 | 消息 | 说明 |
| --- | --- | --- | --- |
| `30016` | `ErrAPIProjectNotFound` | `Project Not Found` | `project_key` 不正确 |
| `1000051686` | `ErrFileInternal` | `file internal error` | 业务错误 |
