# 更新计划表草稿

对已有计划表草稿执行一次更新操作，可新增或删除行、调整顺序与前后序、修改负责人、交付物、排期、估分和实际工时。一次请求只接受一个 `operation`，执行结果可能同步完成，也可能转入异步保存。

## 调用与结果处理

1. 使用[创建计划表草稿](创建计划表草稿.md)取得可用草稿，从[草稿骨架](查询全量计划表草稿骨架.md)读取行 UUID。
2. 选择操作类型及其对应的 `operation_value` 子对象；两者必须配对，不能只替换操作名称。
3. 检查顶层 `err_code`，再检查 `data.status`。`success` 表示完成，`failed` 时读取 `data.msg`，`saving` 时保存 `transaction_id`。
4. 仅异步保存需要调用[更新计划表草稿查询进度](更新计划表草稿查询进度.md)。同步完成时事务 ID 可能为空或不存在。

插件权限位于“权限管理 → 工作项”，见[权限管理](../guides/权限管理.md)。更新草稿与[发布草稿](发布计划表草稿.md)是不同操作。

## 操作类型与载荷配对

| `operation_type` | `operation_value` 下的字段 | 数据组织与约束 |
| --- | --- | --- |
| `AddTaskRows` | `add_task_rows` | 同批任务共享父行与插入位置；每项至少填 `name` 或 `element_key` |
| `AddNodeRows` | `add_node_rows` | 同批资源节点的每个 `element_key` 必填 |
| `AddSubInstanceRows` | `add_sub_instance_rows` | 直接传数组；每行独立指定父行等信息，字段值为 `field_values` JSON 字符串 |
| `AddResourceSubInstanceRows` | `add_resource_sub_instance_rows` | 直接传数组，提供资源库子工作项 ID 列表 |
| `DeleteRows` | `delete_rows` | `delete` 删除；`move_out` 仅支持子工作项，节点与子任务不能移出 |
| `RestoreRows` | `restore_rows` | 使用行 UUID 列表恢复 |
| `AdjustRowOrder` | `adjust_row_order` | 行、父行与前一行共同确定插入位置 |
| `UpdateNodeSequence` | `update_node_sequence` | 设置前序、后序 UUID 列表 |
| `UpdateNodePhase` | `update_node_phase` | 修改单个节点所属阶段 |
| `UpdateNodePhases` | `update_node_phases` | 批量节点共享一个 `phase`，目标节点须允许移入该阶段 |
| `UpdateDismantleMode` | `update_dismantle_mode` | 修改子项拆解模式，模式取值待核实 |
| `UpdateName` | `update_name` | 更新单行名称 |
| `UpdateRoleOwners` | `update_role_owners` | 多行共享同一 `owners`，通过 `link_roles` 建立角色关联 |
| `UpdateDelivery` | `update_delivery` | 设置字段交付物和实例交付物 |
| `UpdatePlannedSchedule` | `update_planned_schedule` | 单行整体或差异化排期 |
| `UpdatePlannedSchedules` | `update_planned_schedules` | 批量整体排期，不支持差异化 |
| `UpdateSchedulePoint` | `update_planned_schedule` | 单行估分使用该载荷，并填写其中的估分对象 |
| `UpdateSchedulePoints` | `update_schedule_points` | 批量整体估分，只接受节点、任务和子工作项 UUID |
| `UpdateScheduleActualTimes` | `update_schedule_actual_times` | 批量整体或差异化实际工时 |

批量 UUID 数组不能是空数组，数组元素也不能是空字符串。同一操作中的 UUID 共用提交值；需要每行不同值时，拆为多次请求，或使用该操作已经定义的行数组 / `items` 结构。

### 排期、估分与实际工时

- 批量计划排期的 `specify_schedule` 与 `preset_offset_schedule` 二选一。指定时间为 UTC 毫秒时间戳，必须大于 0；同时指定起止时，结束不能早于开始。
- 偏移排期的 `type` 仅支持 `start_and_end`、`start_only`、`end_only`；`forward_days` 和 `backward_days` 至少填写一个。
- 批量整体估分必须大于等于 0，单位必须填写；常用 `8` 为天、`9` 为小时。
- `different_schedule` 区分整体与差异化排期或工时。实际工时的 `assignee_type` 为 `0` 整体、`1` 负责人、`2` 参与人、`3` 未分配。
- `pre_uuid` 是前一行 UUID；前一行是父行时，按原文填空。它与 `parent_uuid` 分别表达顺序和层级。

## 请求示例

示例中的数值型脱敏标识已用等长演示数字替代，调用时填写真实 ID；中文数据采用等义 Unicode 转义。

下方按操作分别提供请求示例。HTTP 请求行与 JSON 请求体分开；中文名称与原因采用等义 Unicode 转义，数值型脱敏标识使用演示数字。每个代码块代表一次独立请求。

`UpdateDismantleMode` 的模式枚举尚未定义，具体取值待核实；本篇仅列出已出现的字段，不提供未经确认的调用样例。

## 注意事项

1. operation_type 必须与 operation_value 中的字段对应，不能只修改名称。

2. 批量 UUID 数组不能为空，数组内也不能有空字符串；UpdateSchedulePoints 仅接受节点、任务、子工作项 UUID。

3. 同一批 operation 的所有 UUID 共用相同值。需要每行不同值时，应拆成多次请求或使用 rows/items 型批量结构。

4. 时间单位枚举：0 未知、1 年、2 半年、3 季度、4 双月、5 月、6 双周、7 周、8 天、9 小时、10 分钟、11 秒。
