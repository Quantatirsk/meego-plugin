# 获取指定的工作项列表（跨空间）

跨多个空间搜索同一种工作项类型，可按人员、名称、状态、时间和模板等条件筛选。接口权限位于[权限管理](../guides/权限管理.md)的“工作项”分类。若需一次跨工作项类型搜索，参见[全局搜索](获取指定的工作项列表（全局搜索）.md)。

## 查询范围与容量

传入 `project_keys` 时，在指定且已安装插件的空间中搜索；不传时，在请求头用户有权限且已安装插件的空间中搜索。`work_item_type_key` 是必填的单个类型值，与[单空间查询](获取指定的工作项列表（单空间）.md)的类型数组不同。

单页最多 `50` 条，页码从 `1` 开始；`work_item_ids` 最多 `50` 个。匹配结果超过 `5000` 时返回 `20094`，应收紧条件，不能依靠继续翻页读取超限结果。渠道用户还必须提供 `tenant_group_id`。

### 人员筛选的组合

- `search_user.role`：按指定角色是否包含目标人员筛选。
- `search_user.field_key`：仅支持 `owner`、`watchers`、`issue_operator`、`issue_reporter`。
- 使用 `role` 或 `field_key` 时必须同时提供 `user_keys`；单独给出字段或角色会返回 `20059`。
- 两者都省略时，原文仅支持查询需求角色中包含指定人员的工作项。

扩展工作流信息仅适用于节点流。返回字段按父对象拆表，表内字段名相对于标题给出的路径，数组对象按单个元素阅读。

<a id="field-note-1"></a>

**project_keys**

空间 ID 列表，`project_key` 在飞书项目空间双击空间名称获取。

- 若填了`project_keys`，则查询安装了插件的空间工作项信息。
- 未传`project_keys`，则查询 header 中用户有权限的空间中安装了插件的空间工作项信息。

<a id="field-note-2"></a>

**work_item_status**

工作项状态列表，筛选当前处于列表内状态的工作项实例，遵循[WorkItemStatus](../formats/数据结构汇总.md#9b44f95f)结构规范。可从以下途径获取：

- [获取字段信息](获取字段信息.md)接口中 `work_item_status` 的 `options` 中获取，选择对应的 value。
- [获取创建工作项元数据](获取创建工作项元数据.md)接口中的 `work_item_status` 字段的 `options` 中获取，选择对应的 value。
