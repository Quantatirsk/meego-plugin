## 阅读约定

- `list<T>` 表示数组，`map<K, V>` 表示映射；`Object`、`object`、`interface{}` 是原文的通用值占位，不表示可随意提交任意结构。字段值的真实形状见[字段与属性解析格式](字段与属性解析格式.md)。
- 字段名与枚举区分大小写。`bool` 与 `boolean` 保留原命名；`int64` 不自动转换为字符串，接入端应避免用不能精确表示大整数的类型承接 ID。
- 本页同时描述读和写。标注“作为请求参数”或“更新模式”的规则，仅在实际写接口声明支持时生效；`ExPand` 列出的开关也并非每个查询接口都接受。
- 不同结构的布尔风格枚举不能互换。例如 `FieldValue.disabled` 是 `1` 禁用、`2` 启用，`RelationRule.disabled` 则是 `1` 启用、`2` 禁用。
- 原文有同名但内容不同的 `FinishedInfoItem`，以及基础与扩展两个 `RoleConfDetail`。本地保留各自锚点，重复容器合并引用，不同角色结构按用途区分。

## 字段模型

`FieldValuePair` 承载实例上的值；`SimpleField` 描述字段定义；`FieldConf` 描述表单配置和条件；`FieldValue` 用于维护选项，`Option` / `OptionConf` 用于读取选项及其可见性。选项更新时使用 ID `value`，展示名称 `label` 不替代 ID。

<a id="10c42182"></a>

### FieldValuePair

提交字段时，`field_key` 与 `field_alias` 至少提供一种；富文本的 `field_value` 与 `field_value_markdown` 二选一。`update_mode` 不能理解为所有字段通用的增量更新协议，以下规则仅明确覆盖多人复合字段。

| 字段                   | 类型          | 说明                                                                                                                                                                                                                                              |
| ---------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `field_key`            | `string`      | 字段key，作为请求参数和field_alias二选一必填                                                                                                                                                                                                      |
| `field_alias`          | `string`      | 字段对接标识，作为请求参数和field_key二选一必填                                                                                                                                                                                                   |
| `field_value`          | `Object`      | 字段值，作为请求参数必填，可参考[字段与属性解析格式](字段与属性解析格式.md)                                                                                                                                                                                 |
| `field_value_markdown` | `Object`      | 富文本内容 Markdown 格式，仅富文本字段生效，和 field_value 二选一，可参考 [Markdown 格式说明](https://arcosite.bytedance.net/sites/1698370054562/6552139f9045fa02fe4f6435/editor/6a4c9f3c029ec1050c4d18a6?docLang=zh&bv=656ef48385acee02ee573dac) |
| `field_type_key`       | `string`      | 字段类型，作为请求参数非必填                                                                                                                                                                                                                      |
| `target_state`         | `TargetState` | 指代流转至该目标状态需要填写对应字段，状态流使用，作为请求参数非必填                                                                                                                                                                              |
| `update_mode`          | `int`         | [详细说明](#field-note-3)                                                                                                                                                                                                                         |

<a id="field-note-3"></a>

**update_mode**

**非必填。**更新模式用于控制「本次传入的数据」如何影响字段的最终值。不同字段类型下含义不同。以「多人复合字段」为例，它主要用于区分「全量替换」和「增量更新」。并不是所有字段类型都支持该参数，只有下面提及的字段类型支持该参数。

- 多人复合字段
- 不填：默认为「替换模式」
- `0`：替换模式（本次传入的值会被视为字段的最终状态）
- 自由填写：传入了哪些人，以及这些人对应的子字段值，最终字段值就包含这些人和对应值。
- 固定范围：只更新传入的范围内成员；范围内未传入的成员，其子字段值会被默认清空。也就是说，未传入某个成员 Key，就等同于清空该填写人的字段值。
- `1`：更新模式（本次传入的值只会更新对应成员的数据，不影响未传入的成员）
- 自由填写：如果 `userKey` 是新增的，则新增该人员并设置对应子字段值；如果 `userKey` 已存在，则更新该人员对应的子字段值。
- 固定范围：只更新填写范围内人员的子字段值；如果传入的人员不在填写范围内，则根据业务规则忽略该值，或返回错误。

### NumberConfig

`scaling_ratio` 是显示缩放配置，不改变字段存储值。百分比配置下，原值 `0.011` 显示为 `1.1`；是否补足小数位由 `display_digits` 控制。`symbol_setting` 使用紧随其后的 `SymbolSetting` 定义。

| 字段             | 类型                       | 说明                                                 |
| ---------------- | -------------------------- | ---------------------------------------------------- |
| `scaling_ratio`  | `string`                   | - `"1"`：不缩放，显示原值 [详细说明](#field-note-18) |
| `display_digits` | `int64`                    | - `-1` = 不限 [详细说明](#field-note-19)             |
| `symbol_setting` | [SymbolSetting](#5e1ddeff) | 显示符号配置                                         |
| `thousandth`     | `bool`                     | - `true` 开启千分位 [详细说明](#field-note-20)       |

<a id="field-note-18"></a>

**scaling_ratio**

- `"1"`：不缩放，显示原值
- `"0.01"`：百分比，原值 `0.011` 显示 `1.1`
- `"0.001"`：千分比，原值 `0.001` 显示 `1`
- `"1000"`：千，原值 `10000` 显示 `10`
- `"10000"`：万，原值 `100000` 显示 `10`
- `"1000000"`：百万，原值 `10000000` 显示 `10`

<a id="field-note-19"></a>

**display_digits**

- `-1` = 不限
- `0` = 整数
- `1` = 1位
- `2` = 2位
- `3 `= 3位
- `4` = 4位
- `5` = 5位
- `6` = 6位

<a id="field-note-20"></a>

**thousandth**

- `true` 开启千分位
- `false` 未开启千分位

<a id="field-note-27"></a>

**is_auto**

排期与估分更新模式，不传表示为true

true：

- 若只填写了排期，则自动将估分补充为排期之间的差值
- 若只填写了估分，则会将排期清空
- 若排期、估分均填写，会按所填值落库
- 若排期、估分均未填写，则会将估分置为0、排期清空

false：

- 若只填写了排期，不会将估分补充为排期之间的差值
- 若只填写了估分，不会将排期清空
- 若排期、估分均填写，会按所填值落库
- 若排期、估分均未填写，则视为不做改动，而非清空

<a id="field-note-28"></a>

**actual_work_time**

实际工时，精确到小数点后一位

备注：

- 子任务不支持
