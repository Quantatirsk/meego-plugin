# OpenAPI：凭证与权限

访问凭证确定调用身份，权限和空间授权决定该身份可以访问什么数据。三者缺一不可；获得凭证不代表能够访问任意空间或接口。

## 凭证类型

| 凭证 | 使用场景 | 用户身份 |
| --- | --- | --- |
| `plugin_access_token` | 已安装插件的服务端调用，也可交换用户凭证 | 按目标接口要求额外传 `X-User-Key` |
| `virtual_plugin_token` | 开发与调试 | 与插件凭证相似，但只能访问配置的数据范围 |
| `user_access_token` | 用户授权后代表该用户调用 | 用户身份包含在凭证中 |

OpenAPI 请求使用 `X-Plugin-Token` 传递凭证。使用插件或虚拟插件凭证时，是否还需要 `X-User-Key` 由目标接口决定；使用用户凭证时，不应额外假设所有接口都需要该请求头。

## 获取与保护插件凭证

服务端使用 `POST /open_api/authen/plugin_token`，以 `plugin_id`、`plugin_secret` 和可选 `type` 获取插件凭证。这个初始交换不使用已有的 `X-Plugin-Token`。`type: 0` 为正式插件凭证，`type: 1` 为虚拟插件凭证；完整请求与响应见[获取插件访问凭证](plugin-token.md)。

`plugin_secret` 只能存放在服务端受控的环境变量或密钥系统中。它不能进入前端产物、浏览器缓存、日志、fixture 或 Markdown 示例。服务端应缓存凭证和实际返回的有效期，在临近失效时重新获取；不要依赖重复获取始终返回同一个 token。

用户凭证由客户端获取一次性授权码，再由服务端使用已取得的插件凭证交换。每个授权码只能使用一次，有效期为 5 分钟。用户凭证与刷新凭证的有效期以接口返回为准，具体见[交换用户访问凭证](user-plugin-token.md)和[刷新用户访问凭证](refresh-token.md)。

## 三层授权

| 层次 | 作用 |
| --- | --- |
| 开发数据范围 | 限制虚拟凭证在开发调试时可访问的空间 |
| 接口权限 | 决定插件获准调用哪些 OpenAPI 能力 |
| 发布、安装与空间数据授权 | 决定正式版本能否在目标空间访问数据 |

开发数据范围只提供本地调试所需的一个可访问空间，不等同于正式版本的空间授权。正式使用需要发布插件、由空间管理员安装相应版本，并完成空间数据授权。

申请接口权限前，应在开放平台按能力查看“查看 API”所覆盖的接口，只申请当前功能的最小集合。agent 需要改变权限范围时，必须通过 `lpm` 列出 scope 和影响，并在用户明确确认后执行。

## 实现检查

- 选择与调用场景匹配的 token 类型。
- 将插件密钥和 token 限制在服务端密钥边界。
- 在目标接口文档中确认 `X-User-Key`、权限和数据范围要求。
- 把开发数据范围、接口权限和正式空间授权分别验证。
- 对 token 过期和权限失败保留平台错误信息与日志标识，不输出敏感值。
