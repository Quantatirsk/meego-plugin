# 更新计划表草稿查询进度

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-work-item-wbs-draft-patch-progress-query"></a>
- **更新计划表草稿查询进度** ｜ `openapi.post.open-api-work-item-wbs-draft-patch-progress-query` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

查询一次计划表草稿更新事务的最终结果。仅当[更新计划表草稿](更新计划表草稿.md)返回 `status: "saving"` 时，使用该响应中的 `transaction_id` 调用本接口；同步成功无需查询。

## 事务状态与超时

| `data.status` | 处理方式 |
| --- | --- |
| `saving` | 保存仍在进行，检查等待截止时间 |
| `success` | 本次更新完成 |
| `failed` | 本次更新失败 |

`create_time` 与 `max_saving_ttl` 均为 Unix **秒级**时间戳。`max_saving_ttl` 是绝对截止时刻，不是等待秒数；当前 Unix 秒超过它而状态仍为 `saving` 时，可认为操作超时或失败。不要将其乘算成持续时长，也不要与毫秒时间戳直接比较。

查询的权限位于“权限管理 → 工作项”，见[权限管理](../guides/权限管理.md)。事务不存在时可能返回 `30015`。

## 返回参数

下表的事务字段在成功示例中位于 `data` 下。顶层 `err_code = 0` 仅表明查询请求成功，需继续读取业务 `status`。

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `transaction_id` | string | 更新计划表草稿操作标识，与请求中的 transaction_id 一致 |
| `status` | string | 操作状态：saving 表示保存中，success 表示成功，failed 表示失败 |
| `create_time` | int64 | 操作创建时间，Unix 秒级时间戳 |
| `max_saving_ttl` | int64 | 异步保存允许等待到的绝对 Unix 秒级时间戳；当前 Unix 秒超过该值且状态仍为 `saving` 时，可认为操作超时或失败。该字段不是持续时长，也不是毫秒时间戳。 |
| `err` | object | 对部分错误会在这里进行更详细的错误描述，可协助日志记录和问题反馈。 |
| `err_msg` | string | 错误信息。 |
| `err_code` | int32 | 错误码。 |

### `err`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int32 | 部分场景下，透出更详细错误对应的错误码。 |
| `msg` | string | 部分场景下，透出更详细的错误描述。 |

## 请求示例
