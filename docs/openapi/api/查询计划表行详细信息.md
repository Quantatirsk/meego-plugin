# 查询计划表行详细信息

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-work-item-wbs-view-detail-query"></a>
- **查询计划表行详细信息** ｜ `openapi.post.open-api-work-item-wbs-view-detail-query` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

读取已发布计划表的行详情，一次最多 200 行，超过即报错。先从[查询全量计划表骨架](查询全量计划表骨架.md)取得 UUID，再用字段掩码选择返回内容。

## 实例态读取规则

请求不含 `draft_id`，响应列表为 `data.view_row_details`。草稿数据应使用[查询计划表草稿数据行详细信息](查询计划表草稿数据行详细信息.md)。

实例态额外支持 `custom_fields.*` 和 `custom_fields.<field_key>`，用于选择自定义列。未选中字段可能不返回，不等于业务值为空。权限见[权限管理](../guides/权限管理.md)中的“工作项”。

### 字段掩码

| 类别 | 全量路径 | 可单独选择的字段路径 |
| --- | --- | --- |
| 元信息 | `meta.*` | `meta.uuid`、`meta.type`、`meta.conf_uuid`、`meta.parent_uuid`、`meta.belong_work_item_info`、`meta.deletable` |
| 基本信息 | `base.*` | `base.name`、`base.start_time`、`base.finish_time`、`base.owners`、`base.schedule`、`base.schedule_dependency`、`base.dependencies`、`base.union_deliveries`、`base.process_status` |
| 节点扩展 | `node_extra.*` | `node_extra.is_milestone`、`node_extra.phase`、`node_extra.predecessor`、`node_extra.state_key` |
| 子工作项扩展 | `sub_instance_extra.*` | `sub_instance_extra.dismantle_mode` |
| 自定义列 | `custom_fields.*` | `custom_fields.<field_key>`，替换为实际字段 key |

节点和子工作项扩展掩码分别使用 `node_extra`、`sub_instance_extra` 根路径。实例态没有单独定义 `meta.editable_conf` 掩码。

<a id="返回参数"></a>

## 返回参数

### 响应结构

- `meta` 描述行标识、归属和编辑能力；`base` 描述名称、负责人、排期、依赖、交付物和状态。
- 角色 key 使用 `role_key`，与行详情示例和草稿态相同结构一致。
- 自定义聚合列的返回路径与完整对象结构待核实；已明确的请求掩码为 `custom_fields.*` 或 `custom_fields.<field_key>`。下方复制样例不包含争议返回字段。
- `base.dependencies` 的类型表列 `FF/FS`；排期依赖示例另列 `FF/FS/SF/SS`，两组依赖分开处理。
- 子工作项的 `belong_work_item_info` 为自身，节点、子流程节点和子任务为父工作项。原文提及但未展开的 `LinkedWorkItemInfo` 不新增为参数。

<a id="parameter-notes-1"></a>

**belong_work_item_info 的填写说明**

所属工作项：

里程碑节点、普通节点、子流程节点和子任务的 BelongWorkItemInfo 是父工作项

子工作项： BelongWorkItemInfo 是自己的WorkItem信息，没有LinkedWorkItemInfo

普通节点： BelongWorkItemInfo 是父工作项的WorkItem信息，没有LinkedWorkItemInfo

子流程节点： BelongWorkItemInfo 是父工作项的WorkItem信息，LinkedWorkItemInfo 是自己的WorkItem信息

子任务： BelongWorkItemInfo 是父工作项的WorkItem信息，LinkedWorkItemInfo 是自己的WorkItem信息所属工作项信息
