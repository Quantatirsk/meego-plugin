# 查询计划表草稿数据行详细信息

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-work-item-wbs-draft-detail-query"></a>
- **查询计划表草稿数据行详细信息** ｜ `openapi.post.open-api-work-item-wbs-draft-detail-query` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

根据行 UUID 查询草稿态计划表的详细数据，一次最多 200 行，并使用 `row_field_marks` 选择需要返回的字段。

## 读取顺序与数据范围

1. 使用[查询全量计划表草稿骨架](查询全量计划表草稿骨架.md)取得同一草稿的行 UUID。
2. 将 UUID 按不超过 200 个分组，带上 `draft_id` 查询详情。
3. `row_field_marks` 按下文的字段路径填写，响应记录在 `data.draft_row_details` 中。

本接口的 UUID 来自同一草稿的骨架。插件权限见[权限管理](../guides/权限管理.md)中的“工作项”。

<a id="table-content-1"></a>

### 字段掩码

字段掩码支持 `*` 通配符。以下路径以每个行详情对象为根，不添加 `draft_row_details` 前缀。

| 类别 | 全量路径 | 可单独选择的字段路径 |
| --- | --- | --- |
| 行元信息 | `meta.*` | `meta.uuid`、`meta.type`、`meta.conf_uuid`、`meta.parent_uuid`、`meta.belong_work_item_info`、`meta.editable_conf`、`meta.deletable` |
| 基本信息 | `base.*` | `base.name`、`base.start_time`、`base.finish_time`、`base.owners`、`base.schedule`、`base.schedule_dependency`、`base.dependencies`、`base.union_deliveries`、`base.process_status` |
| 节点扩展 | `node_extra.*` | `node_extra.is_milestone`、`node_extra.phase`、`node_extra.predecessor`、`node_extra.state_key` |
| 子工作项扩展 | `sub_instance_extra.*` | `sub_instance_extra.dismantle_mode` |

`sub_instance_extra` 只作为一层掩码根路径。未选字段不应仅凭缺失就判定为空。

<a id="返回参数"></a>

## 返回参数

### 对象如何对应业务

`meta.type` 区分 `node`、`sub_instance`、`sub_task`；`node_extra` 存放节点信息，`sub_instance_extra` 存放子工作项的拆解方式，示例中 `item` 为事项拆解、`flow` 为流程拆解。

`meta.belong_work_item_info` 对子工作项表示自身，对里程碑、普通节点、子流程节点和子任务表示父工作项。原描述还提到 `LinkedWorkItemInfo`，但本篇参数树没有给出该字段；不据此创建新的响应层级。

`base.schedule` 包含整体与按人员拆分的计划排期、估分、工期和实际工时；数值与单位分开返回，单位完整枚举见文末。`base.dependencies` 是启动完成依赖，`base.schedule_dependency` 是排期依赖，保留为两个集合。

<a id="parameter-notes-1"></a>

**belong_work_item_info 的填写说明**

所属工作项：

里程碑节点、普通节点、子流程节点和子任务的 BelongWorkItemInfo 是父工作项

子工作项： BelongWorkItemInfo 是自己的WorkItem信息，没有LinkedWorkItemInfo

普通节点： BelongWorkItemInfo 是父工作项的WorkItem信息，没有LinkedWorkItemInfo

子流程节点： BelongWorkItemInfo 是父工作项的WorkItem信息，LinkedWorkItemInfo 是自己的WorkItem信息

子任务： BelongWorkItemInfo 是父工作项的WorkItem信息，LinkedWorkItemInfo 是自己的WorkItem信息所属工作项信息
