# 飞书项目 OpenAPI 接入导读

[完整目录](INDEX.md) · [HTTP 接口速查](ENDPOINTS.md) · [阅读入口](README.md)

本页根据同目录中的官方文档整理，用于建立查阅顺序。所有参数、响应结构和例外条件以对应接口详情为准。

## 1. 接入与鉴权

调用链涉及三层条件：插件申请了接口权限，目标空间安装了具有该权限的插件版本，以及操作用户具备相应的数据访问或编辑权限。开发期的虚拟插件凭证可以不依赖目标空间安装，但受插件后台配置的数据范围限制。详见[访问凭证](guides/获取访问凭证.md)和[权限管理](guides/权限管理.md)。

| 凭证 | 用途 | 请求头与获取方式 |
| --- | --- | --- |
| `plugin_access_token` | 插件身份调用、换取用户凭证 | 放入 `X-Plugin-Token`，调用业务接口时搭配 `X-User-Key`；通过插件 ID 和 Secret 获取 |
| `virtual_plugin_token` | 开发调试 | 与插件凭证用法类似；获取插件凭证时传 `type: 1` |
| `user_access_token` | 代表授权用户执行操作 | 放入 `X-Plugin-Token`；用客户端授权码和插件凭证换取 |

相关接口：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/open_api/authen/plugin_token` | 获取插件或虚拟插件凭证 |
| POST | `/open_api/authen/user_plugin_token` | 用授权码换取用户凭证 |
| POST | `/open_api/authen/refresh_token` | 刷新用户凭证 |

插件凭证通常有效 7200 秒，应缓存复用，并按每次返回的 token 与有效期更新；临近过期可能提前更换。授权码有效期为 5 分钟且只能使用一次。用户凭证示例为 7200 秒，刷新凭证示例为 1209600 秒。完整入参与返回值见[获取访问凭证](guides/获取访问凭证.md)。

获取用户授权码的客户端入口为：

```javascript
const { code } = await window.JSSDK.utils.getAuthCode();
```

换取 Token 的 OpenAPI 请求由自建服务端发起。原文要求插件存在客户端构成，以便识别当前操作用户。[授权流程](guides/获取访问凭证.md#3df3fccd)

### 用户权限校验

使用插件或虚拟插件凭证时，部分读接口默认采用兼容模式，可能返回超出 `X-User-Key` 所代表用户权限的数据。需要严格按用户权限读取时，对文档列出的接口使用 `x-auth-mode: 1`。用户凭证始终按对应用户严格校验；该请求头不会改变写接口或未列出的读接口行为。[完整适用范围](guides/x-auth-mode鉴权模式.md)

## 2. 通用协议与响应

域名使用实际访问的飞书项目域名。普通 JSON 接口的公共请求头包括 `Content-Type: application/json`、`X-Plugin-Token`，以及鉴权方式所需的 `X-User-Key`。文件和分片上传的媒体类型、路径、参数位置应单独查阅接口文档。[Open API 概述](guides/OpenAPI概述.md)

写接口支持可选的 `X-IDEM-UUID`，用于同一 `X-Plugin-Token` 下同一接口的幂等判断。文档没有在概述中给出统一的幂等保留时间，不应自行假定。

成功响应的业务判断不能只看 HTTP 状态。不同接口的响应包装不同：鉴权示例使用 `error.code`，不少业务接口使用 `err_code`、`err_msg` 和 `err`；具体以接口“返回参数”和成功、失败示例为准。[凭证响应](guides/获取访问凭证.md)、[工作项详情响应](api/获取工作项详情.md)、[错误码](formats/Open%20API%20错误码.md)

## 3. 领域标识与字段模型

| 标识 | 查找入口 | 用途 |
| --- | --- | --- |
| `project_key` | [空间列表](api/获取空间列表.md)、[空间详情](api/获取空间详情.md) | 空间标识；部分接口也接受 `simple_name`，以各参数表为准 |
| `work_item_type_key` | [获取空间下工作项类型](api/获取空间下工作项类型.md) | 工作项类型标识，不能假定自定义类型都为 `story` |
| `work_item_id` | [工作项搜索](api/获取指定的工作项列表（单空间）.md)、[工作项详情](api/获取工作项详情.md) | 工作项实例标识 |
| `field_key` / `field_alias` | [字段信息](api/获取字段信息.md)、[创建元数据](api/获取创建工作项元数据.md) | 定位字段；是否允许别名及是否二选一由接口定义 |
| `node_id` / `state_key` | [工作流详情](api/获取工作流详情.md)、[流程模板详情](api/获取流程模板配置详情.md) | 节点或状态标识，用于节点操作与状态流转 |
| `user_key` | [用户详情](api/获取用户详情.md)、[用户搜索](api/搜索租户内的用户列表.md) | 飞书项目用户标识 |

字段值不是统一字符串。人员、日期、选项、关联工作项、排期、复合字段、富文本等类型都有对应结构，先查[字段与属性解析格式](formats/字段与属性解析格式.md)，再查[数据结构汇总](formats/数据结构汇总.md)。

富文本和评论的 Markdown 另有平台扩展，包括人员提及、链接预览、文字样式、对齐等。读取富文本 Markdown 的参数也随接口变化，例如工作项详情使用 `expand.need_rich_text_mark_down`，全量搜索使用 `need_rich_text_mark_down`。[Markdown 格式](formats/Markdown%20格式说明.md)、[工作项详情](api/获取工作项详情.md)、[全量搜索](api/获取指定的工作项列表（全量搜索）.md)

## 5. 写入与异步任务

创建工作项前，用[创建元数据](api/获取创建工作项元数据.md)确定该类型所需字段；写入值遵循字段格式。[创建工作项](api/创建工作项.md)、[更新工作项](api/更新工作项.md)

批量更新是异步任务：提交接口返回 `task_id`，随后查询处理进度。一次最多 50 个工作项，且一次修改一个字段；`APPEND`、`UPDATE`、`REPLACE` 支持的字段类型不同。提交与进度查询接口均注明 1 QPS。[批量更新](api/批量更新工作项字段值.md)、[进度查询](api/获取批量更新处理进度.md)

节点完成、回滚和状态流转是不同操作。流转前可读取指定节点或状态的必填表单、子任务、交付物等要求。[节点完成与回滚](api/节点完成与回滚.md)、[状态流转](api/状态流转.md)、[流转必填信息](api/获取指定节点与状态流转所需必填信息.md)

计划表草稿的创建、更新、发布和重置分别有对应的进度查询接口。请按[接口速查](ENDPOINTS.md)中“计划表”分类成对查阅，不能把提交成功直接解释为任务完成。

文件附件、富文本图片、通用文件上传与分片上传属于不同接口组，其文件标识和请求格式不同。[附件上传](api/上传文件或富文本图片.md)、[通用文件上传](api/上传文件.md)、[分片初始化](api/分片初始化.md)

## 6. 事件回调

监听事件、拦截事件、插件装卸以及 AI 事件分别有独立协议。业务事件枚举、触发条件和 payload 完整保存在[事件目录](INDEX.md#events)与[AI 应用目录](INDEX.md#ai)。

普通监听事件文档明确说明：需在 1000 ms 内返回 HTTP 200；失败后重试 4 次，间隔依次为立即、1 分钟、2 分钟、7 分钟；事件可能乱序和重复，可结合 `request_time` 与 `idempotent_key` 处理。视图操作查询可能有 2 秒延迟，指定关联工作项列表查询可能有 1 分钟延迟。[监听事件](events/监听事件.md)

验签按照 `plugin_id`、请求体 `request_time`、回调 Token 的顺序拼接并进行 SHA-256，结果与 `signature` 比较。具体字段及示例见[验签说明](events/事件兼容性与验签.md)。拦截事件具有阻塞业务操作的语义，应单独阅读[拦截事件](events/拦截事件.md)，不要直接套用普通监听回调处理方式。

AI 能力的服务端操作分为[修改节点](ai/修改AI节点数据.md)、[完成节点](ai/完成AI节点.md)、[获取节点](ai/获取AI节点信息.md)、[更新 AI 字段](ai/更新AI字段.md)、[更新 AI 操作状态](ai/更新AI操作运行状态.md)。每组权限、事件结构和链接选项都已在 `ai/` 收录。

## 计划表查询路径

- 查询列配置时，先用[查询计划表配置列](api/查询计划表配置列.md)取得聚合列 key，再用[查询计划表行详细信息](api/查询计划表行详细信息.md)读取行值。
- 查历史快照时，先查[基线列表](api/获取计划表基线列表.md)，再按基线 ID 分页或按 UUID 查[基线详情](api/获取基线详情.md)。
- 查跨计划表引用时，从源工作项调用[被引用父行查询](api/查询实例被引用的父行信息.md)。
