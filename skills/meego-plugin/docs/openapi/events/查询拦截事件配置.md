# 查询拦截事件配置

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.get.open-api-intercept-project-intercept-config-list"></a>
- **查询拦截事件配置** ｜ `openapi.get.open-api-intercept-project-intercept-config-list` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

查询指定空间的精细化拦截规则及空间级禁用状态。此接口无需单独开通接口权限，仍需携带通用鉴权 Header。

以下字段按接口参数表及写入接口统一，错误旧示例已移除。

<a id="请求说明"></a>

## 接口

| 项目 | 值 |
| --- | --- |
| 方法 | `GET` |
| 路径 | `/open_api/intercept/project_intercept_config/list` |
| 配置写入 | [按空间设置拦截事件配置](按空间设置拦截事件配置.md) |

<a id="请求参数"></a>
<a id="header"></a>
<a id="Query"></a>

## 请求参数

Header 见[通用请求头](../guides/OpenAPI概述.md#a8e43b86)。本接口只定义一个 Query 参数，没有定义 `page_size`。

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `project_key` | string | 是 | 空间 key |

<a id="请求示例"></a>

### 请求示例

```http
GET /open_api/intercept/project_intercept_config/list?project_key=650ab62c3b70c530914xxxxf2 HTTP/1.1
Host: project.feishu.cn
```

上例仅展示请求行，实际调用须补齐鉴权 Header。原文把 `GET/open_api/...` 标作 JSON，现改为 HTTP 语法并补上空格。

<a id="返回参数"></a>

## 返回结构

### 顶层

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `data` | `list<object>` | 精细化配置列表，见 [project_intercept_config](../formats/数据结构汇总.md#238b9eee) |
| `disable_intercept` | boolean | 是否禁用当前空间拦截；原表称“当前空间是否拉黑” |
| `err_code` | int32 | 成功为 `0`，失败为实际错误码 |
| `err_msg` | string | 成功为空，失败为错误信息 |
| `err` | object | 详细错误对象，成功时为空 |
| `err.code` | int32 | 部分场景下的详细错误码 |
| `err.msg` | string | 详细错误描述 |
| `err.log_id` | string | 排查调用链所需的日志标识 |

### data[]：一组配置

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `project_intercept_config_id` | string | 配置 ID |
| `events` | `list<int64>` | 事件范围，原文建议按同类事件分组配置 |
| `work_item_type` | `list<string>` | 工作项类型 key |
| `work_item_intercept_config` | `list<object>` | 按类型细化的范围 |

### work_item_intercept_config[]：类型内的条件

完整结构见 [work_item_intercept_config](../formats/数据结构汇总.md#fd963053)。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `work_item_type` | string | 当前条件对应的工作项类型 |
| `fields` | `list<string>` | 修改字段 `1009`、批量修改字段 `1010` 的字段范围，结合 `events` 判断 |
| `template_ids` | `list<string>` | 流程模板列表，适用场景见[写入文档](按空间设置拦截事件配置.md) |
| `node_intercept_config` | `list<object>` | 节点 `2001–2007`、子任务 `4001–4008` 的模板和节点范围 |
| `state_intercept_config` | `list<object>` | 状态流转 `3001` 的模板与流转范围 |

### 节点与状态条件

| 对象 | 字段 | 类型 | 说明 |
| --- | --- | --- | --- |
| `node_intercept_config[]` | `template_id` | string | 节点模板 ID |
| `node_intercept_config[]` | `node_ids` | `list<string>` | 节点 ID 列表 |
| `state_intercept_config[]` | `template_id` | string | 状态模板 ID |
| `state_intercept_config[]` | `transition_ids` | `list<string>` | 要拦截的流转 ID 列表 |

模板版本筛选能力待核实，本页不提供未被参数定义确认的版本字段示例。

## 响应示例

### 成功响应

以下按本接口参数表和写入接口的共同结构整理，展示针对字段修改事件的配置。旧示例中的错误字段名及不匹配事件条件已删除。

```json
{
  "err": {},
  "err_code": 0,
  "err_msg": "",
  "disable_intercept": false,
  "data": [
    {
      "project_intercept_config_id": "111",
      "events": [
        1009
      ],
      "work_item_type": [
        "story"
      ],
      "work_item_intercept_config": [
        {
          "work_item_type": "story",
          "fields": [
            "name",
            "field_2ef0ab"
          ]
        }
      ]
    }
  ]
}
```

### 失败响应

参数错误的响应形状按本页错误表整理；具体详细消息与日志标识以实际响应为准。

```json
{
  "err_code": 20006,
  "err_msg": "Invalid Param",
  "err": {
    "code": 20006,
    "msg": "Invalid Param",
    "log_id": "REPLACE_WITH_LOG_ID"
  }
}
```

<a id="错误码"></a>

## 错误码

| err_code | err_msg | err.code | err.msg | 排查方向 |
| --- | --- | --- | --- | --- |
| `20006` | `Invalid Param` | `20006` | `Invalid Param` | 核对空间 key 与请求格式 |
| `50006` | `RPC Call Error` | `50006` | `biz error: project not found` | 核对 `project_key`；原表消息末尾多了一个引号，已去除排版错误 |

通用错误见 [Open API 错误码](../formats/Open%20API%20错误码.md)。
