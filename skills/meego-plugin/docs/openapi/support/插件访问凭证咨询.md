## 为什么需要 plugin_access_token

调用 OpenAPI 前，需创建插件、申请接口权限并安装到目标空间，才能访问对应空间的数据。`plugin_access_token` 用于识别插件，不会自动赋予任意空间或任意用户的权限。

<a id="25009dcc"></a>

## 插件凭证的有效期与更换

本 FAQ 说明有效期通常为 **2 小时**；剩余不足 **5 分钟**时再次获取会返回新 token，旧 token 仍在自身有效期内有效。到期后重新获取插件凭证即可，不使用用户凭证的 refresh_token 流程。

缓存应依据接口返回的 token 与有效期更新，不依赖两次请求得到相同字符串。[凭证主文](../guides/获取访问凭证.md)已按此规则统一。

## 如何获取 X-USER-KEY

通过[获取用户详情](../api/获取用户详情.md)查询 user key。该接口有适用插件类型的限制，ISV 插件相关问题见[错误码排查](OpenAPI错误码排查.md#34f1aba6)。

<a id="96c7db25"></a>

## X-USER-KEY 需要什么权限

使用插件凭证加 `X-USER-KEY` 调用时，该用户须有目标空间中对应操作的权限。例如仅空间管理员可执行的操作，传入用户也必须具备管理员权限。

部分读取接口另有 [x-auth-mode 鉴权模式](../guides/x-auth-mode鉴权模式.md)；其适用范围以该文的接口清单为准，不能将读取放宽推导到所有接口。

## 如何获取用户凭证与 refresh_token

### 1. 在客户端取得授权码

使用 [getAuthCode](https://project.feishu.cn/b/helpcenter/1p8d7djs/hcok4x6h#21b31584)。取得后传给自己的服务端兑换，避免原示例直接打印授权码。

```javascript
const { code } = await window.JSSDK.utils.getAuthCode();
```

### 2. 在服务端兑换凭证

| 项目 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/open_api/authen/user_plugin_token` |
| Header `Content-Type` | string，必填，`application/json` |
| Header `X-Plugin-Token` | string，必填，插件凭证，格式示例 `p-24af8f8f-290f-4fc7-86e1-b592e46dee43` |
| Body `code` | string，必填，授权码，示例 `c8e2bf5ff54a41509cf97f94c763dc7a` |
| Body `grant_type` | string，必填，固定 `authorization_code` |

以下使用飞书项目平台域名；原文 `{平台域名}` 是需替换的占位符。原 cURL 误标 PowerShell，现标为 shell。

```sh
curl --location 'https://project.feishu.cn/open_api/authen/user_plugin_token' \
  --header 'X-Plugin-Token: p-694b3fcd-5eec-4380-a4e4-9c09699a2c63' \
  --header 'Content-Type: application/json' \
  --data '{
    "code": "7849d137b6d947a5bdee470eedd66e09",
    "grant_type": "authorization_code"
  }'
```

### 3. 读取响应中的 token 与期限

```json
{
  "data": {
    "token": "u-efe05d32-b733-4b15-a960-6acadf8eefbb",
    "expire_time": 7200,
    "refresh_token": "85cde42e-76c8-4677-a783-1e5761f79315",
    "refresh_token_expire_time": 1209600,
    "saas_tenant_key": "DeepCollaboration",
    "user_key": "heguiyan"
  },
  "error": {"code": 0, "msg": "success"}
}
```

| 字段 | 含义 |
| --- | --- |
| `data.token` | 用户访问凭证，FAQ 称 user_access_token |
| `data.expire_time` | 用户凭证有效时长，示例为 7200 秒 |
| `data.refresh_token` | 刷新用户凭证所用凭证 |
| `data.refresh_token_expire_time` | 刷新凭证有效时长，示例为 1209600 秒，即 14 天 |
| `data.saas_tenant_key` | 用户所属租户 |
| `data.user_key` | 用户唯一标识 |
| `error.code` | `0` 成功，非零失败 |
| `error.msg` | 返回码描述 |

`expire_time` 是有效时长，不是 Unix 时间戳。若保存绝对过期时间，需在自己的服务端基于当前时间计算；不要把 `7200` 直接当成时间点。

纯服务端 OpenAPI 调用可使用插件凭证加 `X-USER-KEY`。用户凭证和插件凭证的具体鉴权范围仍按[凭证主文](../guides/获取访问凭证.md)处理，不将两种方式视为在所有接口中完全等价。

<a id="5e84744f"></a>

## 如何刷新用户凭证

先通过上述兑换接口取得 `refresh_token`，再调用[刷新用户凭证接口](../guides/获取访问凭证.md#refresh-token)。本 FAQ 将最长刷新时间描述为 14 天，样例 `refresh_token_expire_time` 对应相同有效时长；实际依据返回值。

<a id="2c6209b8"></a>

## 能否以插件或机器人代替用户

本 FAQ 对普通 OpenAPI 调用明确写“不支持”，要求 `X-USER-KEY` 传具体人员。插件凭证标识调用插件，不代表可以把机器人 ID 填入用户 Header。AI 应用等专门授权规则另见对应权限文档，不由此 FAQ 推导。

<a id="5bc6e9b3"></a>

## 如何获取 project_key 与 simple_name

| 标识 | 获取方式 | 示例 |
| --- | --- | --- |
| `project_key` | 双击空间名称复制 | 以实际复制值为准 |
| `simple_name` | 从空间 URL 路径读取 | `https://project.feishu.cn/doc/overview` 对应 `doc` |

两者用途不同，不要把 URL 短名直接当作空间 key。
