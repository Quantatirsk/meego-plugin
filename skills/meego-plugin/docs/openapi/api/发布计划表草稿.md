# 发布计划表草稿

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-work-item-wbs-draft-publish"></a>
- **发布计划表草稿** ｜ `openapi.post.open-api-work-item-wbs-draft-publish` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

发布已有计划表草稿，将草稿变更提交到实例态。原文说明发布后草稿作废；发布过程异步执行，需要保存发布单 ID 并查询最终状态。

## 全量与部分发布

| 请求中的 `uuids` | 发布范围 | 必须考虑的条件 |
| --- | --- | --- |
| 省略或空数组 | 全量发布 | 草稿无任何变更时返回 `10002`，无需继续查询发布进度 |
| 非空数组 | 部分发布 | 同时包含被发布行依赖的行；缺失依赖时返回 `20004` |

部分发布会过滤没有草稿变更的 UUID。实际进入发布的行以返回的 `publish_uuids` 为准；请求中指定但未进入发布的行列在 `un_publish_uuids`。全量发布或没有实际发布行时，`publish_uuids` 可能为空，不能单凭列表为空判断失败。

## 发布后的查询

从 `data.publish_order_id` 取得发布单 ID，按 `data.recommend_interval_ms` 建议的毫秒间隔调用[计划表草稿发布进度查询](计划表草稿发布进度查询.md)。查询时同时保留本次的空间、工作项和 `draft_id`；发布单 ID 与草稿更新的 `transaction_id` 不是同一种查询参数。

插件权限位于“权限管理 → 工作项”，见[权限管理](../guides/权限管理.md)。

## 请求说明

**请求方式**：`POST`
**请求地址**：`/open_api/work_item/wbs_draft/publish`

<a id="请求参数"></a>

## 请求参数

<a id="a3c53a27"></a>

### 请求头

接口调用的 Header 配置详见[Header](../guides/OpenAPI概述.md#a8e43b86)

<a id="Body"></a>

### 请求体

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| project_key | string | 必须 | 空间 ID（project_key）。<br>- 空间 ID（project_key），在飞书项目空间双击空间名称获取。 |
| work_item_id | int64 | 必须 | 工作项id |
| draft_id | string | 必须 | 草稿id，通过[创建计划表草稿](创建计划表草稿.md)或者[查询全量计划表草稿骨架](查询全量计划表草稿骨架.md)获取 |
| uuids | `list<string>` | 可选 | 不传或空数组表示全量发布；非空表示部分发布 |

<a id="返回参数"></a>

## 返回参数

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `publish_order_id` | string | 发布单 id，用于调用计划表草稿发布进度查询接口 |
| `recommend_interval_ms` | int64 | 推荐的轮询间隔，单位毫秒 |
| `publish_uuids` | `list<string>` | 本次实际进入发布的行 uuid 列表。部分发布场景返回；全量发布或无实际发布行时可能为空。 |
| `un_publish_uuids` | `list<string>` | 请求指定但未进入发布的行 uuid 列表。部分发布时，如果指定行没有草稿变更，会出现在该列表中。 |
| `err` | object | 对部分错误会在这里进行更详细的错误描述，可协助日志记录和问题反馈。 |
| `err_msg` | string | 错误信息。 |
| `err_code` | int32 | 错误码。 |

### `err`

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `code` | int32 | 部分场景下，透出更详细错误对应的错误码。 |
| `msg` | string | 部分场景下，透出更详细的错误描述。 |
| `log_id` | string | 报错场景下的调用链标识符，用于追踪错误发生时的完整调用链路，便于日志记录和问题排查。 |
