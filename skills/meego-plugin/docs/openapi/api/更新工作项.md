# 更新工作项

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.work-item.update"></a>
- **更新工作项** ｜ `openapi.work-item.update` ｜ 频次：高 ｜ 状态：已验证 ｜ 示例：[`openapi.work-item.update.fixture`](<../../../fixtures/openapi/work-item-update.json>)

<!-- capability-metadata:end -->

更新一个已存在工作项的指定字段。可编辑字段可从[创建工作项元数据](获取创建工作项元数据.md)获取，接口权限位于[权限管理](../guides/权限管理.md)的“工作项”分类。模板、投票字段不支持修改，已终止工作项也不能直接更新。

## 调用边界

更新会修改平台业务数据。先读取字段元数据并确定目标实例当前值，再在服务端执行调用；只有用户明确了目标空间、实例、字段和值，才应发起真实更新。通用 Header 中如使用 `X-Idem-UUID`，每次请求应使用唯一值，它只能协助识别重复传输，不能替代业务幂等。

本端点正文没有把 `X-User-Key` 或 `x-auth-mode` 定义为固定契约。错误样例中涉及用户标识只是一个失败原因，不能倒推出所有更新请求都必须使用该 Header。

## 覆盖范围与更新模式

`update_fields` 必填，每项以 `field_key` 或 `field_alias` 标识目标字段。默认 `update_mode: 0` 会替换该字段原值；更新 `role_owners` 时，若要保留其他角色，也必须携带其原有数据。

多人复合字段支持两种写法：替换模式携带现有填写人和新增填写人的完整数据；更新模式 `1` 仅提交要补充的填写人数据。下面两组示例使用同一目标，分别展示是否需要带回填写人 A。

富文本值使用 `field_value` 或 `field_value_markdown` 二选一。选项字段写选项 `value`，级联选项还要满足配置层级；字段权限、计算字段或失效选项可能导致更新被拒绝，具体见错误表。

**project_key**

空间 ID（project_key），或者空间域名（simple_name）。

- 空间 ID（project_key），在飞书项目空间双击空间名称获取。
- 空间域名（simple_name），`simple_name` 一般在飞书项目空间 URL 中获取。例如空间 URL 为 “https://project.feishu.cn/doc/overview”，则 `simple_name`为 “doc”。

<a id="field-note-2"></a>

**update_mode**

字段的更新模式，用于控制字段值的更新方式。支持的取值如下所示。

- `0`：替换模式，提交的字段值将完全替换原有值；
- `1`：更新模式，仅更新提交的字段值，不影响其他字段。

默认值：`0`（替换模式）

| ------------------- | -------------- | -------- | ------------------------- |
| `markdown`          | `string`       | 可选     | 富文本内容 Markdown 格式  |
| `mention_user_keys` | `list<object>` | 可选     | 富文本中 @ 提到的人员信息 |

| `user_key` | `string` | 可选     | 对应的人员的 user_key |

<a id="7b8578e8"></a>

## 注意事项

1. 当请求参数中存在级联单选或级联多选字段时，传入的选项值需满足空间配置中该字段的“可选层级”配置。

2. 写接口中选项类型字段的 `field_value` 应传入的是选项 id（value），而非选项的名称（label）。

3. **角色和人员**字段（role_owners）
   1. **流程角色配置的**“允许用户自行增删”**未勾选**，使用**创建和更新**接口时，未传入该字段时**会**自动计算角色和成员的默认值。

   2. **流程角色配置的**“允许用户自行增删”**勾选**，使用**创建和更新**接口时，未传入该字段时**不会**自动计算角色与成员的默认值。

4. 不支持模版、投票字段修改。

完整的占位请求和成功、失败结果见本地 fixture：[更新工作项](../../../fixtures/openapi/work-item-update.json)。字段不存在时可见 `30009 / Field Not Found`；不要自行拼造平台错误对象或假设固定 HTTP 成功状态码。

## 行业专版产品关系

行业专版可独立更新产品关系，关系参数不受 `update_fields` 约束。更新非产品工作项用 `parent_product.work_item` 设置所属产品。更新 `productsystem` 用 `contained_work_items.work_items` 覆盖包含工作项集合。省略外层对象保留旧关系，显式传入外层对象且内部记录为空时清空关系。设置目标时使用大于零的工作项 ID。
