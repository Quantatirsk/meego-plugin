# 获取工作项操作记录

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-op-record-work-item-list"></a>
- **获取工作项操作记录** ｜ `openapi.post.open-api-op-record-work-item-list` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

查询一个空间内最多 50 个工作项的操作历史，可按操作者、触发来源、动作、模块和时间筛选。接口授权位于[权限管理](../guides/权限管理.md)的“工作项实例”分类，工作项概念见[官方名词解释](https://project.feishu.cn/b/helpcenter/1p8d7djs/4bsmoql6#92679309)。

## 时间范围与续查

不能查询 2024-07-02 之前的历史记录。`start`、`end` 使用毫秒时间戳，两者限定的时间区间最长 7 天；查询更长时段需要拆分区间。

首次请求省略 `start_from`，之后使用响应返回的同名值继续读取，并以 `data.has_more` 判断是否还有记录。单页默认 50 条、最多 200 条。

### 区分操作者与渠道

`operator_type` / `operator` 表示谁触发操作；`source_type` / `source` 表示操作渠道。例如用户标识使用 `user_key`，自动化规则使用规则 ID，插件渠道使用插件 ID。前端操作没有渠道信息，不能强求每条记录都有 `source`。

### 读取变更内容

`record_contents.object` 是直接变更对象，`belong_object` 是其所属对象。例如修改复合字段子字段时，直接对象是子字段，所属对象可指向父字段。`old` / `new` 的基础值和引用 ID 均以字符串返回；`add` / `delete` 当前只用于节点或子任务负责人与角色联动变更。`extra` 当前补充回滚原因。

<a id="field-note-1"></a>

**operator**

操作者的值，用于筛选实例下对应操作者的操作记录：

- 操作者类型为user时，使用用户的 user_key；
- 操作者类型为auto时，使用自动化规则的 ID。

<a id="field-note-2"></a>

**operator_type**

操作者类型，用于标识操作记录的触发来源。支持的取值如下所示。

- `user`：用户操作；
- `auto`：自动化规则触发操作；
- `system`：系统触发操作；
- `calc_field`：计算字段触发操作；
- `plugin`：插件操作；
- `others`：其他触发来源（如空间关联规则）。

<a id="field-note-3"></a>

**source_type**

操作渠道类型，用于标识操作记录的来源渠道。支持的取值如下所示。

- `auto`：来自自动化规则渠道；
- `plugin`：来自插件渠道。

<a id="field-note-4"></a>

**source**

操作渠道值，用于标识操作记录的具体来源。

- 当 `source_type` 为 `auto` 时，使用自动化规则的 ID；
- 当 `source_type` 为 `plugin`时，使用插件的 ID。

- 修改角色与人员
- 修改评论
- 修改负责人的属性：包括节点 负责人的排期、估分、实际工时
- create

- 创建子任务
- delete

- 删除子任务
- terminate
- 终止工作项
- restore
- 恢复工作项
- complete
- 完成节点
- 完成节点子任务
- rollback
