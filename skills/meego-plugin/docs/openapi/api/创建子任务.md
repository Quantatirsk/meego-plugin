# 创建子任务

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-project-key-work-item-work-item-type-key-work-item-id-workflow-task"></a>
- **创建子任务** ｜ `openapi.post.open-api-project-key-work-item-work-item-type-key-work-item-id-workflow-task` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

在指定工作项的一个节点上创建子任务，成功后 `data` 返回新建的子任务 ID。最少需要定位工作项、填写 `node_id` 与 `name`；负责人、排期、备注和自定义字段可按需提交。

## 负责人和排期的填写规则

节点负责人分配方式为“与角色联动”时填写 `role_assignee`，其他方式填写 `assignee`，不能同时设置。产品行为见[新增任务](https://project.feishu.cn/1ykiuvvj/40gyakm8#%E6%96%B0%E5%A2%9E%E4%BB%BB%E5%8A%A1)，权限申请见[权限管理](../guides/权限管理.md)中的“工作项实例”。

`schedule.is_auto` 默认 `true`。它影响省略值的处理方式，不能把省略估分或排期一概理解成保留原值：

| 提交内容 | `is_auto = true`（默认） | `is_auto = false` |
| --- | --- | --- |
| 只有排期 | 估分补为排期间差值 | 不自动补估分 |
| 只有估分 | 清空排期 | 不清空排期 |
| 排期与估分都有 | 按提交值写入 | 按提交值写入 |
| 排期与估分都没有 | 估分置 0，排期清空 | 不做改动 |

<a id="parameter-notes-1"></a>

**is_auto 的填写说明**

排期与估分更新模式，不传表示为 true

true：

- 若只填写了排期，则自动将估分补充为排期之间的差值

- 若只填写了估分，则会将排期清空

- 若排期、估分均填写，会按所填值落库

- 若排期、估分均未填写，则会将估分置为0、排期清空

false：

- 若只填写了排期，不会将估分补充为排期之间的差值

- 若只填写了估分，不会将排期清空

- 若排期、估分均填写，会按所填值落库

- 若排期、估分均未填写，则视为不做改动，而非清空
