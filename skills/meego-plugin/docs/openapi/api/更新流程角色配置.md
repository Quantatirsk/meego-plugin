# 更新流程角色配置

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-project-key-flow-roles-work-item-type-key-update-role"></a>
- **更新流程角色配置** ｜ `openapi.post.open-api-project-key-flow-roles-work-item-type-key-update-role` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

按角色 ID 或对接标识更新流程角色配置。外层标识定位已有角色，内层 `role` 提交名称、成员分配和锁定范围等新配置。

## 使用前确认

- `role_id` 与外层 `role_alias` 至少提供一个；同时提供时优先使用 `role_id`。
- 外层 `role_alias` 用于查找，内层 `role.role_alias` 用于修改对接标识，两者用途不同。
- `member_assign_mode=2` 必须提交非空 `members`；其他模式不应提交 `members`。
- `lock_scope` 可锁定整个角色或基本信息、角色、成员、权限板块；锁定属性仅当前插件可改。

对应的平台功能介绍详见[常见问题：角色管理](https://project.feishu.cn/1ykiuvvj/py7go937)。对应的权限申请在 权限管理-流程角色 分类下，相关功能介绍详见[权限管理](../guides/权限管理.md)。

## 请求说明

- 请求方式：POST

- 请求地址：/open_api/:project_key/flow_roles/:work_item_type_key/update_role

## 请求参数

### Header

接口调用的 Header 配置详见[Header](../guides/OpenAPI概述.md#a8e43b86)。

### Path

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |

| `work_item_type_key` | string | 必须 | 工作项类型，系统自动生成，可以从[获取空间下工作项类型](获取空间下工作项类型.md)接口获取。 |

<a id="parameter-note-1"></a>

**project_key：说明**

空间 ID（project_key），或者空间域名（simple_name）。
- 空间 ID（project_key），在飞书项目空间双击空间名称获取。
- 空间域名（simple_name），`simple_name` 一般在飞书项目空间 URL 中获取。例如空间 URL 为 “https://project.feishu.cn/doc/overview”，则 `simple_name`为 “doc”。

<a id="Body"></a>

### Body

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `role_id` | string | 可选 | 流程角色 ID，可以通过[获取流程角色配置详情](获取流程角色配置详情.md)获取。<br>与 `role_alias` 必填一个，两个都传入则优先使用角色 ID。 |
| `role_alias` | string | 可选 | 角色对接标识，可以通过[获取流程角色配置详情](获取流程角色配置详情.md)获取。<br>与 `role_id` 必填一个，两个都传入则优先使用角色 ID。 |
| `role` | object | 必须 | 更新角色配置信息，参见[RoleConfUpdate](../formats/数据结构汇总.md#3fd5b6f8)结构规范。 |

#### `role` 的字段

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 可选 | 流程角色名称 |
| `is_owner` | boolean | 可选 | 是否为需求负责人 |
| `role_alias` | string | 可选 | 角色对接标识 |
| `member_assign_mode` | int32 | 可选 | [说明](#parameter-note-2) |
| `members` | `list<string>` | 可选 | 指定分配成员的 `user_key` 列表，当成员分配方式为 `2`（默认分配为指定人员）时必传，其他分配方式传参将被拦截。 |
| `is_member_multi` | boolean | 可选 | 是否允许多人，`false` 表示限制为单人 |
| `auto_enter_group` | boolean | 可选 | 成员是否自动入群 |
| `lock_scope` | `list<string>` | 可选 | [说明](#parameter-note-3) |

<a id="parameter-note-2"></a>

**member_assign_mode：说明**

流程角色的成员分配方式。默认值为 `1`（自行添加）。支持的分配方式如下所示。
- `1`：自行添加；
- `2`：默认分配为指定人员；
- `3`：默认分配为创建人。

<a id="parameter-note-3"></a>

**lock_scope：说明**

锁定范围，用于控制哪些属性只能由**当前插件**修改。传值后，该角色不能被管理员删除，默认值为空。
取值范围：all / basic / role / member / auth（all 与其它取值互斥，若传递 all 和其他的，则按照 all 进行处理）
含义：
- all：整个角色配置全部锁定
- basic：锁定「基本信息」板块，包含「角色名称」、「角色 ID」、「对接标识」
- role：锁定「角色配置」板块，包含「角色出现方式」、「允许角色自定增删」、「需求负责人」
- member：锁定「成员配置」板块，包含「成员分配方式」、「限制为单人」、「成员自动入群」
- auth：锁定「权限配置」板块，包含「配置权限规则」、「编辑计划表」、「发布计划表」、「回滚作为节点负责人的节点」

## 请求示例

```json
{
  "role_id": "PM",
  "role_alias": "",
  "role": {
    "name": "\u4efb\u52a1",
    "is_owner": true,
    "auto_enter_group": true,
    "member_assign_mode": 2,
    "members": [
      "REPLACE_WITH_USER_KEY"
    ],
    "is_member_multi": false,
    "role_alias": "",
    "lock_scope": []
  }
}
```
