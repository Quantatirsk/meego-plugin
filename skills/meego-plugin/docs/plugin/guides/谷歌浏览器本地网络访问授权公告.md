# 谷歌浏览器本地网络访问授权公告

本公告发布于 2025-11-27，说明 Chrome 142 上线本地网络访问权限后对插件和本地调试的影响。原页记录该版本于 2025-10-28 发布；Google 的[官方说明](https://developer.chrome.com/blog/local-network-access)也确认权限提示在 Chrome 142 上线。

公告讨论的是公网来源页面连接本地网络或本机回环地址的请求。是否命中限制取决于地址空间和浏览器版本，不能只根据域名是否含“公司”或“内网”判断。

<a id="fceb846b"></a>

## 受影响的表现

<a id="310ff866"></a>

### 普通页面

浏览器可能提示站点要“查找并连接到本地网络上的任何设备”。允许后该权限不再阻止符合条件的请求；拒绝后，目标解析到本地网络的请求可能失败，错误包括 `LocalNetworkAccessPermissionDenied`。

允许权限并不保证服务在线，也不解除 TLS 证书、网络连通性或 CORS 的独立限制。

<a id="f6704474"></a>

### iframe 内嵌页面

iframe 中可能没有直接出现授权弹窗，却发生请求失败或页面无法加载。原页错误示意为：公共网页连接专用网络设备或服务器的请求被禁止。

需要同时检查顶层页面的授权与 iframe 权限委派，不能以“没有弹窗”认定浏览器没有启用限制。

<a id="f26932ff"></a>

## 公告中的适配方式

| 场景 | 处理顺序 |
| --- | --- |
| 插件请求公司内网站点或本地接口 | 确认当前站点的本地网络权限，未授权时引导用户完成授权，再尝试访问 |
| 插件嵌入本地或公司内网页面 | 在加载 iframe 前处理站点授权，并按浏览器支持情况为嵌套 iframe 委派本地网络访问权限 |

原公告给出的 iframe 属性为 `allow="local-network-access *;"`。以下修正原代码的多余符号并使用明确的演示地址；部署时替换为实际内网站点。

```html
<iframe
  src="https://intranet.example.test/"
  title="Internal application"
  allow="local-network-access *;"
></iframe>
```

这段配置记录 2025 年公告使用的权限策略名称，并不保证所有后续浏览器版本完全一致。`*` 是该 iframe 权限策略的来源范围，不是无需用户同意的授权；子 iframe 也不能自行扩大祖先页面未授予的权限。

原文没有提供统一可用的权限查询或主动弹窗 JavaScript API，因此本篇不编造 `navigator.permissions` 的可复制检测实现。接入具体浏览器版本时按其官方支持方式验证。

## 调试时如何区分问题

| 观察结果 | 优先检查 |
| --- | --- |
| 本地网络权限被拒绝 | 当前站点权限、顶层页面授权和 iframe 委派 |
| `ERR_CERT_AUTHORITY_INVALID` | 开发服务证书及本机信任链 |
| 服务连接失败或连接被拒绝 | 地址、端口、开发服务监听与网络可达性 |
| 预检或实际请求缺少正确 CORS 头 | 自建服务或网关的跨域配置 |

具体站点授权入口见[开发调试咨询](<开发调试咨询.md#76e6a460>)。原 FAQ 另一个“权限被拒绝”入口已合并到同节，锚点仍可访问：[控制台权限错误](<开发调试咨询.md#727405c1>)。
