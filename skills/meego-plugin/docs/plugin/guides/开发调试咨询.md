## 基本概念

<a id="040be74a"></a>

### 产物版本与插件版本

产物版本是构建并上传的客户端工程版本，插件发布时选择对应产物。原工具链使用 `lpm release` 打包上传；产物上传成功不等于插件发布完成，见[发布插件](<发布插件.md>)。

<a id="bdefe7e8"></a>

### ResourceID 的作用

ResourceID 把平台构成的运行位置关联到工程资源，对应 `plugin.config.json` 中 `resources[].id`。排查时应同时核对平台配置和资源入口，不要把它与插件 ID 混用。

<a id="a4183c33"></a>

### 获取基础上下文

`spaceId`、`workItemId`、`workObjectId` 通过当前点位 JSSDK 获取，见[客户端 API 概述](<../jssdk/客户端 API 概述.md>)。[Context](<../jssdk/Context.md>) 提供全局信息；空间和工作项字段是否存在取决于 [Control](<../jssdk/Control.md>)、[Tab](<../jssdk/Tab.md>)、[Button](<../jssdk/Button.md>) 等点位场景。

<a id="e821a64c"></a>

### user_key 为什么有不同形式

原文按历史划分：2021 年 6 月前使用的用户可能使用邮箱前缀，之后用户使用数字串。无论外观如何，都应按字符串存储 `user_key`，不转为数字。

原页给出的获取入口为个人头像复制和[获取用户详情](<../../openapi/api/获取用户详情.md>)。界面入口可能随版本变化；用户标识不是用户密码。

<a id="78f8aa03"></a>

### 开发语言

原客户端工程采用 TypeScript + React。服务端语言不限，按 HTTP 接口契约调用；官方 SDK 覆盖与安装方式见[服务端 SDK](<../../openapi/guides/服务端SDK.md>)，不把旧 FAQ 列举的 Go、Java 当作永远不变的完整清单。

<a id="8102611d"></a>

### 与平台保持一致的样式

优先使用[客户端组件库](<../components/客户端组件库接入.md>)提供的基础及业务组件。原页也推荐 [Semi UI](https://semi.design/zh-CN/start/introduction)。组件库的运行时注入要求与普通 UI 依赖不同，应分别处理。

<a id="4637e893"></a>

### 离职账号的调用身份

原文要求停止使用离职账号的 user_key 和 token 作为有效调用身份。历史数据中的用户标识与当前可用授权是两回事；这条要求不表示应删除历史记录中的 user_key。

<a id="1d49a54e"></a>

## 工具排障

先确认当前使用哪一份 `lpm`、其版本和项目目录，避免把不同包管理器安装的启动脚本混用。

<a id="15b7009c"></a>

### Windows 提示找不到 lpm

安装成功但提示“不是内部或外部命令”时，检查 npm 全局可执行文件目录是否加入 PATH。原文的查询命令修正为：

```sh
npm config get prefix
```

在系统的环境变量设置中编辑用户或系统 `Path`，加入查询到的全局目录，保存后打开新终端重试。不要把找不到命令直接认定为包安装失败。

<a id="8d298f32"></a>

### CLI 提示版本过时

`Your Lark Project CLI version ... is out of date` 表示已安装版本落后。原页的升级命令为：

```sh
npm install --global @lark-project/cli@latest
```

升级会改变全局工具版本，应同时阅读新版 CLI 的登录、配置和发布流程。

<a id="3ba14342"></a>

### 命令执行异常或启动脚本来源不明

macOS / Linux 使用 `command -v lpm`，Windows 命令提示符使用 `where lpm` 定位当前命令。检查其所属安装目录与包管理器，再修复实际使用的那一份安装。

不同系统和包管理器的包装脚本不同，不能只因脚本内容或路径不同就判为损坏。

<a id="8620b804"></a>

### 初始化失败，包含 Request failed 或 EPROTO

先检查 `lpm --version`，再检查到 `https://api.github.com/repos/` 的 HTTPS 访问。原模板初始化依赖 GitHub，请允许所需子路径；`ping` 不能验证 HTTPS、代理或 TLS 是否正常，原文这项判断已修正。

原页提供两个可用方向：在能访问 GitHub 的机器初始化后复制工程，或由网络环境允许模板请求。其当时说明客户端产物上传走飞书项目网络地址；不能因此推断后续所有 CLI 操作都不访问 GitHub。

依赖安装失败时，检查 Node、npm / Yarn 的路径及是否存在多套环境。只修正冲突的安装和 PATH，原文“卸载所有 Node 环境”不作为默认处理步骤。

<a id="42734fd5"></a>

### 上传提示 pluginSecret must be encrypted

这是原密钥配置模式的错误。对应工具要求通过配置命令设置密钥，而非把明文直接写入 `plugin.config.json`。

```sh
lpm config set pluginSecret "REPLACE_WITH_PLUGIN_SECRET"
```

上例是占位参数；新版 OAuth 工作流按实际 CLI 文档处理，不将旧密钥配置作为所有新工程的前提。

<a id="906ce122"></a>

### 上传提示 resourceId missing

平台配置了某个客户端资源，但工程 `plugin.config.json` 缺少对应 `resources[].id`。核对平台构成资源和本地配置，补齐正确入口；不要通过随意删除平台构成消除错误。

<a id="6fd16cc5"></a>

### 上传提示 No permission

旧密钥模式下核对插件 ID 和对应 Plugin Secret，必要时用上一节命令重新设置。原页提及 `lpm config get pluginSecret` 可查看配置；该命令可能显示敏感值，不应把输出放进共享日志。新版登录身份与权限问题按 CLI 认证机制排查。

<a id="5c8fc6a6"></a>

### CSS 构建出现包含 basedir 的 BrowserslistError

原错误包含 `Unknown browser query`，查询内容却是启动脚本片段，属于工具安装或包装脚本混入配置的异常。原页建议用原包管理器卸载其全局 CLI，再用 npm 安装。

```sh
pnpm remove --global @lark-project/cli
npm install --global @lark-project/cli@latest
```

仅在确认当前全局包由 pnpm 安装时使用第一条；原文将包名写为 `cll` 的笔误已修正。先保留相关错误日志，不能把该历史症状泛化成所有 CSS 构建问题的原因。

<a id="bc4dc88e"></a>

### 上传成功但后台看不到产物

检查 `plugin.config.json` 的 `pluginId` 是否指向当前插件，`siteDomain` 是否匹配当前开放平台站点，原例为 `https://project.feishu.cn`。确认后刷新对应插件的产物列表，避免在另一个站点或插件下查找。

<a id="04f1da32"></a>

### 环境变量与多环境业务配置

原 FAQ 没有提供通用的业务配置按环境切换机制，可由工程脚本实现。不能把这句话解释为 Node 进程不接受环境变量：同页明确使用 `NODE_OPTIONS`、`LPM_ORIGIN_FOR_DEV_SERVER`，它们各自控制运行内存和旧开发服务地址。

<a id="b0e1c55e"></a>

### heap out of memory

可通过 Node 的 `--max-old-space-size` 调整堆上限，单位 MB，并为系统及其他进程留出内存。下例保留原文 8192 MB 的演示额度和旧启动命令，不表示所有机器都应使用此值。

```sh
NODE_OPTIONS=--max-old-space-size=8192 lpm start
```

Windows 对应使用环境变量设置方式，原文使用 `cross-env`：

```sh
npx cross-env NODE_OPTIONS=--max-old-space-size=8192 lpm start
```

`npx` 可能需要可用的 npm 网络或已安装的 `cross-env`。增大堆上限不能替代检查持续增长的内存占用。

<a id="9782923d"></a>

## 本地调试

<a id="6229191c"></a>

### 构成入口或插件调试信息不展示

按顺序检查：调试空间是否正确；开放平台是否开启本地调试；空间管理员是否能在插件管理页看到调试信息；资源配置是否匹配。

若刷新仍不显示，在浏览器 Network 面板过滤 `plugin/info`。`net::ERR_CERT_AUTHORITY_INVALID` 指向开发证书信任问题，应核对本机开发工具生成的 `MeegleDeveloperPlatform` 根证书。

原工具链在 macOS 钥匙串中设置该开发根证书信任；Windows 在重新运行 `lpm start` 时提供安装提示。仅处理自己开发工具生成的证书，菜单和路径以实际版本为准。

<a id="10a924dc"></a>

### 已有入口但提示网络无法连接

先区分实际请求地址：普通本机 IPv4 地址无法连接时，检查开发服务是否监听、网络是否可达及证书是否被信任；不要仅凭网络错误页面认定是证书问题。原文 Chrome 证书管理入口为 `chrome://certificate-manager`。

| 系统 | 原工具链证书位置 |
| --- | --- |
| macOS | `/Users/<username>/.Meegle_Developer_Platform_CA/meegle_root_ca.crt` |
| Windows | `C:\Users\<username>\.Meegle_Developer_Platform_CA\meegle_root_ca` |

macOS 的点号目录默认隐藏，可在文件选择器中显示隐藏文件。若工具版本已改变证书生成方式，以实际安装产物为准。

若请求误指向 `0.0.0.0`，应使用可访问的实际本机地址。macOS 可在网络设置或 `ifconfig` 查看 IPv4；Windows 使用 `ipconfig`。原 CLI 支持通过下列变量指定地址，示例地址需要替换：

```sh
LPM_ORIGIN_FOR_DEV_SERVER=192.168.1.10 lpm start
```

```sh
npx cross-env LPM_ORIGIN_FOR_DEV_SERVER=192.168.1.10 lpm start
```

端口以开发服务输出为准，不能把旧资料记录的 `3339` 当作所有版本固定端口。

<a id="da17d2d5"></a>

### 内容渲染不正确

检查 `plugin.config.json` 中资源 `id` 与 `entry`，以及平台构成的 ResourceId。组件为 undefined 时，再检查[组件库加载顺序](<../components/客户端组件库接入.md>)。

<a id="76e6a460"></a>
<a id="727405c1"></a>

### 提示授权调试或本地网络访问被拒绝

若出现授权弹窗，按调试需求允许当前飞书项目站点访问本地网络。曾拒绝或未显示弹窗时，到该站点设置检查本地网络权限，再重新加载页面；详见[本地网络访问授权公告](<谷歌浏览器本地网络访问授权公告.md>)。

原错误文字中的 `Pemission` 是拼写问题，应按实际控制台的 `Permission` 与完整错误核对。这一机制与 CORS、HTTPS 证书分别检查，不能用放宽跨域替代网络授权。

## 跨域处理

客户端访问不同源的自建服务时，需要服务端或网关返回匹配的 CORS 响应。并非“所有插件请求一定跨域”，判断依据是请求 Origin 与目标源；原文的绝对表述已修正。

### Nginx 配置

以下是 HTTPS 终止之后网关中的 `location` 配置示意。`backend` 为已定义的上游，Origin 和请求头需按实际请求调整。CORS 响应头集中在同一级，避免原示例在 `if` 内定义 `add_header` 后丢失父级 CORS 头。

```nginx
location / {
    add_header Access-Control-Allow-Origin "https://projectplg.feishupkg.com" always;
    add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;
    add_header Access-Control-Allow-Headers "Authorization,Content-Type,DNT,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Range" always;
    add_header Access-Control-Expose-Headers "Content-Length,Content-Range" always;
    add_header Access-Control-Max-Age 1728000 always;

    if ($request_method = OPTIONS) {
        return 204;
    }

    proxy_pass http://backend;
}
```

继承规则依据 [Nginx add_header](https://nginx.org/en/docs/http/ngx_http_headers_module.html#add_header)。本段不是完整站点配置；响应头应由一层统一管理，避免网关与后端重复发送冲突的 Allow-Origin。

### 后端配置

原页以 Spring Boot 3.3.x 为例，提供全局 `WebMvcConfigurer.addCorsMappings`、控制器 `@CrossOrigin`、方法 `@CrossOrigin` 三种位置。完整全局示例见[入门教程的跨域处理](<开发并发布第一个插件.md#cdca4b85>)。选择一种符合工程范围的配置，不复制原页带省略号和错误 `ResponseVO<string>` 的不完整 Java 片段。

<a id="65ee224c"></a>

### 前端直接调用 OpenAPI

原文明确不支持插件前端直接访问服务端 OpenAPI。客户端可用的数据能力通过 `window.JSSDK` 获取；需要服务端接口时，由自建后端持有插件凭证并调用，再向前端提供业务接口。浏览器修改响应头不能代替正确的调用架构。

<a id="42d8cbca"></a>

### 请求显示 CORS 错误

在 Network 面板分别检查预检 OPTIONS 和实际请求：请求 Origin、方法、请求头是否被允许，实际响应或错误响应是否带正确 CORS 头。正式修复落在服务端或网关。

原页通过浏览器扩展修改响应头作临时定位，以下保留其示意图。它只改变测试浏览器的观察条件，不能证明其他用户可正常访问。携带凭据时不能使用 Allow-Origin 通配符，详见 [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS)。

<a id="ebe12f34"></a>

### 来源白名单

原页给出的公有环境插件来源是 `https://projectplg.feishupkg.com`；私有化环境使用对应部署站点来源。配置前仍需核对浏览器实际发送的完整 Origin，不能把站点域名列表直接当作任意子域名通配授权。

## 开发场景

<a id="2e68fcd7"></a>

### 新建页控件的必填校验

原文提供插件 2.0 的服务端校验思路：控件加载后将 UUID 与业务数据保存到自建服务；配置工作项新建拦截事件，在拦截中按 UUID 查询并校验；实例创建完成的 Webhook 再关联 UUID 与实例 ID。具体回调配置和字段见[控件 Control](<../points/控件 Control.md>)与[拦截事件](<../../openapi/events/拦截事件.md>)。

该方案依赖新建页控件先加载，不能在控件尚未出现时直接提交。简洁模式下需要在设置中显示对应字段与控件。原文说明插件 1.0 不支持这套方案；它也没有给出未加载控件时的通用 UUID 回退协议。

<a id="6c8d1e91"></a>

### 跳转到对应业务系统页面

可在实例详情增加链接类型字段，由插件按业务规则生成 URL 并写入该实例字段。直接从插件发起导航时使用 [navigation](<../jssdk/navigation.md>)，不能用受沙箱限制的 `window.open` 代替。

<a id="f24b7666"></a>

### 配置生效工作项范围

按构成专篇与开放平台当前配置选择工作项类型。按钮、控件等可指定相应类型；是否允许全部、多选或自定义类型取决于构成，不保留旧 FAQ 对“导航和标签一律只能选一个”的概括。

<a id="99bb1324"></a>

### 同类构成能否添加多个

不能按“同类一律只能一个”判断。官方 [Button](<../points/按钮 Button.md>) 明确允许多个按钮；[自动化连接器](<../points/自动化连接器 Connector.md>)允许多个触发器和操作；[拦截点位](<../points/拦截事件 Intercept.md>)可订阅多个事件。其他构成的数量限制以其专篇与配置校验为准，不为未经确认的限制额外新建插件。

<a id="5e76ab4e"></a>

### 当前产物格式不适配插件 2.0

原例是插件 2.0 工程残留旧版插件 `manifest.json` 导致产物格式错误。确认文件确为旧插件构建配置后移除该旧配置，使用 `plugin.config.json`。不要据文件名删除应用本身或其他工具使用的 manifest；新版工程按自己的构建配置排查。

<a id="78eb87d4"></a>

### 监听工作项表单值变化

使用插件 2.0 的 `window.JSSDK.control.onWorkItemFormValueChanged`，支持点位、最多监听字段数和键类型见 [Control](<../jssdk/Control.md>)。下面修正原例中取消函数越出作用域的问题，调用方在退出相应生命周期时执行返回的清理函数。

```typescript
import { FieldType } from '@lark-project/js-sdk';

export async function watchName(): Promise<() => void> {
  const unwatch = await window.JSSDK.control.onWorkItemFormValueChanged(
    { watchKeys: [{ key: 'name', type: FieldType.text }] },
    changedValue => console.info('Form values changed', changedValue),
  );
  return () => unwatch();
}
```

<a id="420c9a11"></a>

### 在右侧打开工作项详情

使用 [navigation.openWorkItemDetailPage](<../jssdk/navigation.md>) 并按其参数控制详情打开方式；不是直接拼接未知内部路由。

<a id="245b6cc4"></a>

### 事件幂等与响应

监听和拦截必须按各自契约处理，不能使用旧 FAQ 合并后的“JSON 响应、最多三次重试”规则。

| 事件类型 | 已明确的处理规则 |
| --- | --- |
| [监听事件](<../../openapi/events/监听事件.md>) | 1000 ms 内返回 HTTP 200，响应体不限；失败最多重试四次，间隔为立即、1、2、7 分钟；用 `data.idempotent_key` 做重复投递去重 |
| [拦截事件](<../../openapi/events/拦截事件.md>) | 按同步响应契约及时返回；同一键可能对应后续同类操作，缓存结论需结合业务状态与有效期，不能永久去重后直接放行 |

<a id="6e0c8f1b"></a>

### searchId 的有效期与数量

本 FAQ 快照声明 `searchId` 不设过期时间，每个插件最多 10 万个。这是 2026-01-13 的服务额度说明，不等同于不可调整的接口类型约束；容量规划前应核对平台当前规则。条件与空间、工作项类型的绑定关系见[工作项筛选器](<../components/工作项筛选器 WorkItemFinder.md>)。
