# 日志检索

插件管理员与协作者可在开发者后台查询当前插件的服务端 API 调用日志、平台事件推送日志。企业自建插件和市场插件均支持该功能。

<a id="ce59dd18"></a>

## 查询范围

| 日志类型 | 记录内容 | 适合排查 |
| --- | --- | --- |
| 服务端接口日志 | 插件调用开放平台 API 的执行时间、URL、返回状态、耗时和错误信息 | 请求失败、超时、错误码 |
| 事件日志 | 平台推送事件的时间、类型、日志标识、返回状态、耗时和重试次数 | 推送失败、重复推送、延迟 |

两类日志均只支持查询**最近 7 日**，每次导出不超过 **500 条**。这是平台 API 与事件的日志范围，不等同于插件前端控制台、自有后端完整日志或客户端构建日志。客户端调试见[开发调试客户端](<../client/开发调试客户端.md>)。

<a id="7b3d2735"></a>

## 检索服务端接口日志

1. 在开发者后台打开目标插件详情。
2. 选择“数据 > 日志检索”。
3. 在“服务端接口日志”页填写条件并点击“查询”。

各条件均选填，默认空值表示不按该项过滤；例如请求 URL 为空时，会查询符合其他条件的全部 API。

| 条件 | 填写方式 |
| --- | --- |
| 执行时间 | 最近 7 日内的时间段 |
| 请求 URL | 选择 HTTP 方法与路径，例如 `[Post]/open_api/user/query` |
| 返回状态 | 成功、失败等调用状态 |
| 错误码 | API 返回的错误码 |
| 空间 ID | `project_key`；双击空间名称获取，多个值通过回车继续添加 |
| 租户 ID | 跨租户查询时使用，取用户凭证响应中的 `data.saas_tenant_key` |
| Log ID | API 调用日志标识，获取方式见下文 |
| 操作人 | `user_key`，按调用身份获取 |

### 获取 Log ID

优先记录 API 响应 Header 中的 `X-Tt-logid`。报错时，响应 Body 也可能提供日志标识，例如接口定义的 `err.log_id`；具体路径按对应 API 响应结构读取。

### 获取租户与操作人

- 自己的 `user_key`：在空间中双击自己的用户头像获取。
- 使用 `plugin_access_token` 的调用：从该请求的 `X-USER-KEY` 获取所传用户标识。
- 使用 `user_access_token` 的调用：使用凭证交换响应中的 `data.user_key`；同一响应的 `data.saas_tenant_key` 是用户所属租户。

授权码需由服务端交换为用户凭证后才能得到这些响应字段，不能直接从 code 字符串推导用户或租户。完整流程见[获取访问凭证](<../../openapi/guides/获取访问凭证.md>)。部分插件凭证只读调用涉及兼容鉴权模式，实际身份语义见 [x-auth-mode](<../../openapi/guides/x-auth-mode鉴权模式.md>)，不要把客户端任意用户标识当作日志已记录的操作人。

### 查看结果与导出

结果包含执行时间、请求 URL、返回状态、执行耗时、错误码和错误信息。

1. 点击记录左侧展开按钮，查看详细调用信息。
2. 点击“导出数据”导出当前查询结果，最多 500 条；超出时先缩小查询条件。

<a id="61a5ff03"></a>

## 检索事件日志

在相同“日志检索”页面切换到“事件日志”，填写条件后点击“查询”。各条件均选填，时间范围限最近 7 日。

| 条件 | 填写方式 |
| --- | --- |
| 推送时间 | 最近 7 日内的时间段 |
| 拦截/监听事件 | 选择事件类别 |
| 事件类型 | 支持多选；编号及定义见[拦截事件](<../../openapi/events/拦截事件.md>)与[监听事件](<../../openapi/events/监听事件.md>) |
| 返回状态 | 例如拦截校验通过、拦截校验拦截、失败 |
| 租户 ID | 跨租户查询时使用 `saas_tenant_key` |
| 空间 ID | `project_key`；双击空间名称获取，回车可添加多个 |
| 工作项 ID | 在实例右上角更多菜单中选择 ID 获取，回车可添加多个 |
| Log ID | 事件回调 Body 中的日志 ID，例如顶层 `log_id` |

`log_id` 用于定位推送日志；`data.idempotent_key` 用于事件幂等去重。两者不是同一个标识，不应拿幂等键替代面板要求的 Log ID。

查询结果包含推送时间、事件类型、返回状态、推送延时和重试次数。点击记录左侧展开按钮查看详情；“导出数据”同样最多导出 500 条。

## 常见问题

<a id="e4650a18"></a>

### 导出失败

每次最多导出 500 条。先按时间、接口、事件类型、空间或其他条件细化查询，再导出；原文未定义超过上限时自动截断、分页导出或文件格式。

<a id="a62f19ec"></a>

### 监听事件记录缺失或没有 data

两种延迟需要分开看：

- 监听事件执行失败时，需等该事件的重试完成后才能查询执行记录。
- 原文说明监听事件的 `data` 在执行 **30 分钟后**支持查询，刚发生时缺少详情不直接等于推送内容为空。

当前[监听事件稳定性规则](<../../openapi/events/监听事件.md#d07da6a4>)为首次投递后最多重试 **4 次**，间隔依次为立即、1 分钟、2 分钟、7 分钟。该规则不适用于拦截事件或自动化连接器。

先核对事件类别、推送时间与日志标识，再在重试结束或详情可查询后重新检索。30 分钟是日志详情可见条件，不是回调响应时限，也不是业务 API 回查一致性延迟。

<a id="c158fe3a"></a>

### 一个 Log ID 查不到整批操作

一次批量操作会产生多个事件和多个 Log ID。单个 Log ID 只能定位对应日志，不能依此取回整批操作的所有事件。

可结合时间段、空间、工作项和事件类型查找关联记录。原文没有提供一个固定的批次聚合 ID，不能自行把某个事件日志或幂等键当作批次标识。
