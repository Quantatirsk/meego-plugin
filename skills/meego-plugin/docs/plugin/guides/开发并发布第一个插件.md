# 开发并发布第一个插件

本篇是飞书项目插件的通用生命周期。先用[快速开始](<快速开始.md>)完成首次环境和工程初始化；需要某个点位、JSSDK 方法或 OpenAPI 端点时，再进入对应细粒度文档。本篇不绑定具体业务场景、前端框架或服务端语言。

## 生命周期

| 阶段 | 结果 | 核对重点 |
| --- | --- | --- |
| 创建插件 | 获得插件身份和管理权限 | Plugin ID、Plugin Secret、协作人和基本信息 |
| 添加构成 | 确定平台入口和资源配置 | 点位、工作项范围、适用端、ResourceId |
| 初始化工程 | 生成与当前插件关联的客户端工程 | `plugin.config.json` 与后台资源映射 |
| 开发与调试 | 在测试空间验证客户端和服务端功能 | JSSDK 上下文、OpenAPI 权限、错误处理 |
| 上传与发布 | 客户端产物关联到插件版本并可被安装 | 产物版本、发布版本、可见范围和安装结果 |

## 1. 创建插件并取得凭证

在飞书项目开放平台创建插件，随后进入该插件的“基本信息”。已知 Plugin ID 时，页面地址形如：

```text
https://project.feishu.cn/openapp/MII_<plugin-id>#app_key
```

在该页的“插件凭证”区域获取：

- **Plugin ID**：插件身份标识，用于工程关联和服务端认证。
- **Plugin Secret**：用于受控的本地 `lpm` 配置和服务端密钥环境。

不要把 Plugin Secret 写进客户端源代码、浏览器存储、日志、测试 fixture 或提交到仓库。初始化命令可能包含密钥，应按敏感数据处理；客户端发布产物中也不能包含该值。凭证交换和缓存规则见[获取访问凭证](<../../openapi/guides/获取访问凭证.md>)。

基本信息、协作人和发布前展示资料见[创建插件](<创建插件.md>)。

## 2. 添加插件构成

进入当前插件的“插件功能”页。已知 Plugin ID 时，页面地址形如：

```text
https://project.feishu.cn/openapp/MII_<plugin-id>#app_feature
```

选择功能构成后，完成其平台配置：

1. 选择点位，并确认网页端或移动端支持。
2. 设置名称、工作项范围和其他点位特有字段。
3. 为每个客户端构成记录 ResourceId。
4. 需要 OpenAPI 时，申请与实际端点对应的权限；需要事件或自动化时，配置服务端回调。

后台 ResourceId 必须等于 `plugin.config.json` 中对应资源的 `resources[].id`；`entry` 则是该资源的客户端入口文件。构成 Key 不是 ResourceId，不能混用。完整配置规则见[添加插件功能](<添加插件功能.md>)和[初始化插件工程](<../client/初始化插件工程.md>)。

## 3. 初始化并开发客户端

在“插件功能”页复制平台生成的初始化命令，在本地执行以创建工程。安装和登录官方开发工具的步骤见[环境准备](<环境准备.md>)；初始化后的资源映射、配置变更和 `lpm update` 用法见[初始化插件工程](<../client/初始化插件工程.md>)。

在工程根目录启动本地调试：

```sh
lpm start
```

开启平台本地调试后，在测试空间把构成放入对应布局或入口。客户端入口应先等待宿主共享模块，再按点位使用 `window.JSSDK` 获取上下文；不要在浏览器中直接调用需要 Plugin Secret、平台访问凭证或用户刷新凭证的 OpenAPI。调试过程见[开发调试客户端](<../client/开发调试客户端.md>)。

## 4. 按需接入服务端和 OpenAPI

以下任一需求都需要自有服务端：调用 OpenAPI、交换用户授权码、保存敏感数据、接收事件/拦截/自动化回调，或执行不适合浏览器完成的异步任务。

服务端负责：

1. 从受控配置读取 Plugin ID 和 Plugin Secret，获取并缓存平台凭证。
2. 校验自有客户端请求和平台回调，按接口要求调用 OpenAPI。
3. 将客户端的一次性授权码换取用户凭证；用户凭证和刷新凭证只保存在服务端。
4. 为客户端提供最小化的业务接口，返回前端真正需要的数据。

客户端经由服务端调用 OpenAPI 的边界是：`客户端 -> 自有服务端接口 -> 飞书项目 OpenAPI`。服务端应为实际功能定义明确接口和输入校验，不接受由客户端任意指定 OpenAPI 路径、请求头或平台凭证的透传请求。

开发环境可以使用受限测试空间、虚拟插件凭证和仅用于本地调试的受信任来源配置，以减少联调阻力；仍不能把平台密钥下发到浏览器。生产环境应使用明确的来源、路由、请求头和权限白名单，以及请求鉴权、受控密钥存储、超时限制和脱敏日志。CORS 只限制浏览器跨域访问，不构成身份认证。

服务端认证、用户授权和完整请求/响应示例见[获取访问凭证](<../../openapi/guides/获取访问凭证.md>)；端点目录见[OpenAPI 文档库](<../../openapi/README.md>)；事件协议见[监听事件](<../../openapi/events/监听事件.md>)。

## 5. 联调和发布

联调至少覆盖：

1. 平台构成是否出现在预期点位和端上。
2. ResourceId、客户端入口和 JSSDK 上下文是否匹配。
3. OpenAPI 权限、用户身份和失败响应是否按实际接口处理。
4. 服务端凭证、回调校验、超时和日志是否符合环境边界。

客户端调试通过后，在工程根目录构建并上传产物：

```sh
lpm release
```

该命令生成的是**客户端产物版本**。随后回到开放平台创建插件发布版本，选择已上传的产物、配置使用范围并提交发布。发布完成后，空间管理员在允许范围内安装插件，再在真实点位验证已发布版本。详细规则见[发布插件产物](<../client/发布插件产物.md>)和[发布插件](<发布插件.md>)。
