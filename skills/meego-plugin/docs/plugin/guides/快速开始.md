# 从零开发飞书项目插件

本页是首次开发的最短路径。已存在插件工程时，直接按当前点位、JSSDK 或 OpenAPI 需求进入对应页面，不要重新初始化工程。

<a id="environment"></a>

## 1. 准备本地环境

先完成[环境准备](环境准备.md)：确认 Node.js、包管理器和飞书项目 CLI 可用，并执行 `lpm --version`。需要自建服务端时，再准备目标服务框架和本地 HTTPS/CORS 调试条件；服务端不是所有插件的前置条件。

<a id="console-credentials"></a>

## 2. 取得 Plugin ID 与 Plugin Secret

打开当前插件的[插件凭证页面](<https://project.feishu.cn/openapp/MII_67C9518C5F818002#app_key>)。该链接对应当前示例插件；开发其他插件时，将 URL 中的 `MII_67C9518C5F818002` 替换为目标 Plugin ID。

Plugin ID 用于关联本地工程，Plugin Secret 用于 `lpm` 初始化和服务端换取插件凭证。Secret 可以保存在本机受控的 `lpm` 配置或服务端密钥配置中，但不能出现在浏览器代码、前端产物、日志、fixture、Git 或 CI 输出中。`plugin_access_token`、`user_access_token` 和 `refresh_token` 始终只在服务端保存。

<a id="plugin-feature"></a>

## 3. 添加插件构成

打开当前插件的[插件功能页面](<https://project.feishu.cn/openapp/MII_67C9518C5F818002#app_feature>)，选择需要的页面、控件、Tab、按钮、配置页、字段类型、事件或连接器。具体选择见[添加插件功能](添加插件功能.md)。

为客户端构成配置 ResourceId、目标工作项范围和 Web/Mobile 支持端。ResourceId 连接控制台构成与本地 `plugin.config.json` 中的 `resources[].id`；它不是显示名称，也不能与构成 Key 互换。

<a id="initialize"></a>

## 4. 初始化并同步工程

在插件功能页面复制初始化命令，或在本机执行以下形式的命令：

```text
lpm init <project-name> <plugin-id> <plugin-secret> --site-domain https://project.feishu.cn
```

初始化完成后，检查 `plugin.config.json` 的 `resources[].id -> entry` 映射。控制台新增构成后，在工程根目录执行 `lpm update`，再实现新增入口。详细规则见[初始化插件工程](../client/初始化插件工程.md)。

<a id="implementation"></a>

## 5. 实现客户端与服务端

客户端代码从当前点位的 JSSDK context 开始：资源点决定 namespace、可用字段和端支持范围。先查[插件点位](../points/)和[JSSDK](<../jssdk/客户端 API 概述.md>)，再写 UI 和本地状态。

需要读写平台数据时，浏览器调用自建服务端，自建服务端持有平台凭证并调用 OpenAPI。先查[OpenAPI 凭证](../../openapi/guides/获取访问凭证.md)、[权限管理](../../openapi/guides/权限管理.md)和[接口速查](../../openapi/ENDPOINTS.md)；代理和安全分层见[服务端与 OpenAPI 代理](../../../references/service-boundary.md)。

<a id="debug-release"></a>

## 6. 调试、构建与发布

在工程根目录执行 `lpm start` 调试本地客户端，分别验证已声明的网页端与移动端构成。构建产物、上传、创建插件版本、安装和空间授权是不同阶段；继续阅读[开发调试客户端](../client/开发调试客户端.md)、[发布插件产物](../client/发布插件产物.md)和[发布插件](发布插件.md)。
