# 客户端开发限制

插件客户端同时受资源额度和运行沙箱限制。资源额度涉及产物包及客户端 API 调用；下文沙箱能力矩阵针对网页端，不能套用为移动端或服务端 OpenAPI 的限制。

**阅读导航**：[资源额度](#5cc46307) · [沙箱范围](#3fe36525) · [模式差异](#mode-differences) · [浏览器能力](#browser-capabilities) · [替代入口](#alternatives)

<a id="5cc46307"></a>

## 客户端资源额度

这些额度不会随着插件使用量自动扩展，设计时需要控制资源体积和调用频率。

<a id="dbe55847"></a>

### 产物包：最大 50 MB

一个插件的客户端产物包含其所有功能实现，最大为 **50 MB**，不是每个功能分别享有 50 MB。

原文建议：需要更大体积的资源时，自行提供资源存取服务，在客户端使用 JavaScript 动态加载。该建议不解除浏览器与沙箱的其他限制。

<a id="ad02ea86"></a>

### 单个客户端 API：20 QPS

单个客户端 API 的调用限制为 **20 QPS**。应控制重复查询和高频事件触发的调用数量。

原文未进一步定义该额度按用户、插件实例还是其他维度共享，也未说明限流窗口算法，相关计数维度待核实。此处不是服务端 OpenAPI 限流；服务端规则见 [OpenAPI 概述](<../../openapi/guides/OpenAPI概述.md#rate-limits>)。

<a id="3fe36525"></a>

## 沙箱规则的适用范围

插件发布后，其客户端产物运行在平台提供的沙箱中。官方将以下规则限定于**网页端**，并说明移动端不受这组网页沙箱规则影响；这不表示移动端具备所有浏览器能力，移动端仍按各 JSSDK 方法的支持说明使用。

表中的“允许”仅表示平台开放该沙箱能力，不保证浏览器在任何条件下都执行成功。浏览器兼容性、用户授权和交互条件仍可能影响调用。模式定义见[客户端术语](<客户端术语.md>)与[脚本模式](<脚本模式.md>)。

<a id="mode-differences"></a>

### 自定义界面与脚本模式的差异

| 策略 | 自定义界面模式 | 脚本模式 | 作用 |
| --- | --- | --- | --- |
| `allow-downloads` | 允许 | 不允许 | 通过带 `download` 属性的链接或导航下载文件，包含点击及脚本触发的下载 |
| `allow-forms` | 允许 | 不允许 | 表单提交；未开放时，表单可以显示，但提交相关功能受阻 |
| `allow-pointer-lock` | 允许 | 不允许 | 使用 [Pointer Lock API](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_Lock_API) |
| `allow="geolocation"` | 允许 | 不允许 | 获取地理位置信息 |

### 两种模式均允许的策略

| 策略 | 作用与边界 |
| --- | --- |
| `allow-scripts` | 允许运行脚本；不能由此推导允许创建浏览器弹窗 |
| `allow-same-origin` | 不因沙箱策略被强制视作特殊的不透明来源；不能由此推导允许使用平台明确禁止的 localStorage |

`allow-same-origin` 影响同源判定，参考[同源策略](https://developer.mozilla.org/en-US/docs/Web/Security/Same-origin_policy)。它与下文列出的本地存储限制是不同层次的规则。

<a id="browser-capabilities"></a>

### 两种模式均不允许的沙箱策略

| 策略 | 受限能力 |
| --- | --- |
| `allow-modals` | 浏览器原生 `alert()`、`confirm()`、`prompt()`、`print()`；也涉及 `beforeunload` 事件能力 |
| `allow-orientation-lock` | 锁定屏幕方向 |
| `allow-popups` | `window.open()`、链接 `target="_blank"` 等直接打开新窗口的操作；原文说明可能静默失败 |
| `allow-popups-to-escape-sandbox` | 由沙箱打开、不继承沙箱标记的新浏览上下文 |
| `allow-presentation` | 通过 [Presentation API](https://developer.mozilla.org/en-US/docs/Web/API/PresentationRequest) 启动演示会话 |
| `allow-storage-access-by-user-activation` | iframe 通过 [Storage Access API](https://developer.mozilla.org/en-US/docs/Web/API/Storage_Access_API) 请求非分区 Cookie |
| `allow-top-navigation` | 导航顶级浏览上下文，包括 `_top` |
| `allow-top-navigation-by-user-activation` | 由用户手势触发顶级导航 |
| `allow-top-navigation-to-custom-protocols` | 导航到浏览器内置或网站注册的非 HTTP 协议 |

原生 `<dialog>` 不等同于 `window.alert/confirm/prompt`；原文明确 `allow-modals` 不决定 `<dialog>` 是否允许使用，因此不应把该策略解读成“所有页面内弹层都禁止”。

### 两种模式均不允许的权限策略

| 策略 | 受限能力 | 原文说明的失败表现 |
| --- | --- | --- |
| `allow="autoplay"` | 无用户交互的媒体自动播放 | `HTMLMediaElement.play()` 的 Promise 拒绝；音视频元素的 `autoplay` 属性不能生效 |
| `allow="camera"` | 摄像头输入 | `MediaDevices.getUserMedia()` 的 Promise 以 `NotAllowedError` 拒绝 |
| `allow="encrypted-media"` | 加密媒体扩展 EME | `Navigator.requestMediaKeySystemAccess()` 的 Promise 以 DOMException 拒绝 |
| `allow="fullscreen"` | 通过 `Element.requestFullscreen()` 请求全屏 | Promise 以 `TypeError` 拒绝 |
| `allow="microphone"` | 麦克风输入 | `MediaDevices.getUserMedia()` 的 Promise 以 `NotAllowedError` 拒绝 |
| `allow="midi"` | Web MIDI | `Navigator.requestMIDIAccess()` 的 Promise 以 DOMException 拒绝 |
| `allow="payment"` | Payment Request API | 被权限策略禁止时，`PaymentRequest` 构造函数抛出 `SecurityError` |

全屏方法名依据 [requestFullscreen](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen) 修正；支付错误条件依据 [PaymentRequest 构造函数](https://developer.mozilla.org/en-US/docs/Web/API/PaymentRequest/PaymentRequest#exceptions) 修正为“被策略禁止时”，不再保留原文相反的描述。

### localStorage：两种模式均不允许

一个平台页面可能同时运行多个插件沙箱，且沙箱域名相同。平台为避免不同插件共用同一存储区域而禁止直接使用 `localStorage`，应改用 [window.JSSDK.storage](<../jssdk/storage.md>)。

`storage` 有独立的隔离、容量和账号切换规则，应按其文档处理。允许 `allow-same-origin` 不会解除此项限制。

<a id="alternatives"></a>

## 常见需求的替代入口

| 需求 | 官方建议 | 边界 |
| --- | --- | --- |
| 提示或确认 | 使用 `window.JSSDK.modal.confirm`，见官方 [modal](<../jssdk/modal.md#77fa264a>) | 替代原生 `alert/confirm`，按 JSSDK 参数与回调处理 |
| 打开页面 | 使用 [window.JSSDK.navigation.open](<../jssdk/navigation.md>) | 不使用沙箱内 `window.open`；支持的 target 见导航 API |
| 打印 | 用导航 API 在新标签页展示待打印内容，再由新页面调用 `window.print()` | 打印发生在新页面，不是在插件沙箱内 |
| 客户端缓存 | 使用 [window.JSSDK.storage](<../jssdk/storage.md>) | 按插件与用户隔离，并处理存储失败 |

上述替代入口也受运行模式约束：[脚本模式](<脚本模式.md#supported-api>)的主入口支持清单不包含 `navigation.open` 或 `modal.confirm`，因此打开页面、打印和确认弹窗的方案不能直接套用到脚本主入口。
