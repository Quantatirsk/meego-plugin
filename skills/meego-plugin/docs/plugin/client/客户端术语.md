# 客户端术语

本页统一插件客户端开发中的入口、API 和资源术语。它们描述的是插件运行环境与代码加载关系，不是服务端 OpenAPI 的资源类型。

| 术语 | 含义 | 相关文档 |
| --- | --- | --- |
| `entry` | 客户端代码入口；需结合配置位置区分入口文件与导出函数 | [入口的两种含义](#table-content-1) |
| `client API` | `window.JSSDK` 提供的客户端能力，包含上下文、通用能力和数据模型 | [客户端 API 简介](<../jssdk/客户端 API 概述.md>) |
| `client components` | 可在插件环境中使用的客户端组件 | [客户端组件库接入](<../components/客户端组件库接入.md>) |
| `sharedModules` | 插件主动向运行环境提供的共享模块，例如 React、ReactDOM | [shared](<../jssdk/shared.md>) |
| `injectedModules` | 平台根据共享模块依赖与运行环境，注入到插件中的资源，例如客户端组件库 | [共享与注入的关系](#shared-and-injected) |
| 沙箱 | 平台用于运行插件资源的隔离环境，其能力受平台策略限制 | [客户端开发限制](<客户端开发限制.md#3fe36525>) |

## entry：入口文件与导出函数

`plugin.config.json` 中的 `entry` 指向客户端代码入口文件。入口文件通过默认导出或具名导出，提供可执行的入口函数。

```typescript
export default () => {
  // Default entry function.
};

export function Demo() {
  // Named entry function.
}
```

示例只展示两种导出方式，不包含界面渲染。在其他 API 的参数中，`entry` 也可能指导出函数名：例如官方 [modal.open](<../jssdk/modal.md#def9b6b7>) 使用入口文件导出的模块名，不应把工程文件路径直接当作同一个参数传入。

<a id="shared-and-injected"></a>

## sharedModules 与 injectedModules

两者方向不同：

1. 插件调用 `window.JSSDK.shared.setSharedModules(...)`，主动共享 React、ReactDOM 等模块。
2. 平台根据已共享的模块和当前运行环境，识别可用的注入资源。
3. 依赖满足后，平台加载这些资源；插件应等待共享配置的异步调用结束，再消费对应资源。

客户端组件库就是注入资源的一种。共享 React/ReactDOM 后，还要按[组件库接入](<../components/客户端组件库接入.md>)要求安排惰性加载与导入顺序；仅安装类型包不能替代运行时注入。
