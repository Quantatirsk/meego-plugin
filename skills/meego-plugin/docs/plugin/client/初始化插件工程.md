# 初始化插件工程

使用 `lpm init` 创建与开放平台插件关联的客户端工程。初始化会同步该插件在开发者后台的功能构成，生成配置和入口代码；后续开发工具根据 `plugin.config.json` 中的资源映射构建各端产物。

<a id="d063f61f"></a>

## 前提条件

- 已完成[客户端开发环境准备](<../guides/环境准备.md#53942104>)。
- 已在开放平台[创建插件](<../guides/创建插件.md>)。
- 已[添加插件构成](<../guides/添加插件功能.md#e3ac4ff2>)；目标插件的功能页地址以 `#app_feature` 结尾。

<a id="e53232f1"></a>

## 创建工程

1. 在开放平台的“插件功能”页（当前插件地址以 `#app_feature` 结尾）点击“复制初始化命令”。
2. 在本地终端执行命令，开发工具会在当前目录下创建指定名称的工程目录。

命令形式如下，尖括号表示需要替换的参数，并非命令的字面内容：

```text
lpm init <project-name> <plugin-id> <plugin-secret> [options]
```

| 参数或选项 | 必填 | 说明 |
| --- | --- | --- |
| `project-name` | 是 | 新建目录名称；仅允许字母、数字、下划线和连字符 |
| `plugin-id` | 是 | 工程关联的插件 ID，初始化时同步该插件的后台构成配置 |
| `plugin-secret` | 是 | 插件密钥 |
| `--site-domain` | 是 | 创建插件的站点地址；私有化环境必须使用对应部署站点 |
| `--template-id` | 否 | 工程模板标识，例如 `onboarding`、`react-empty` |
| `--force` | 否 | 是否覆盖已存在的同名目录，默认 `false`；使用前确认目标目录内容可被替换 |

示例中的插件凭证是占位值，实际使用后台复制的命令：

```sh
lpm init plugin-demo MII_REPLACE_WITH_PLUGIN_ID REPLACE_WITH_PLUGIN_SECRET --site-domain https://project.feishu.cn
```

插件 ID 与密钥均在“开发者后台 > 插件详情页 > 插件凭证”中获取。凭证页地址为 `https://project.feishu.cn/openapp/<plugin-id>#app_key`，其中 `<plugin-id>` 替换为目标插件 ID。

`pluginSecret` 仅供本地 LPM 配置及服务端使用，不是前端运行时配置。实际密钥不得进入浏览器代码、客户端构建产物、日志、fixture、Git 或 CI 输出；自动化构建应从 CI 的密钥管理机制注入，并确保输出已脱敏。平台访问凭证和刷新凭证同样只能保留在服务端。

## 工程组成

<a id="3111b734"></a>

### 推荐目录

`src` 内部结构是推荐组织方式，不是强制目录协议。具体构成名称和入口以初始化结果与 `resources` 配置为准。

```text
plugin-demo/
|-- global.d.ts
|-- package.json
|-- plugin.config.json
|-- src/
|   |-- api/
|   |   |-- auth.ts
|   |   `-- index.ts
|   |-- common/
|   |   |-- components/
|   |   `-- hooks/
|   |-- constants/
|   |   |-- index.ts
|   |   `-- translation.json
|   |-- features/
|   |   |-- buttons/
|   |   |   |-- button-a/
|   |   |   `-- button-b/
|   |   `-- tab/
|   `-- utils/
|       |-- helper.ts
|       `-- index.ts
`-- tsconfig.json
```

| 路径 | 职责 |
| --- | --- |
| `global.d.ts` | 全局通用类型声明 |
| `package.json` | npm 包配置、依赖和脚本 |
| `plugin.config.json` | 插件元信息和功能构成到代码入口的映射 |
| `src/api` | 接口调用与网络层 |
| `src/common` | 共用组件、React Hooks |
| `src/constants` | 常量及翻译数据 |
| `src/features` | 各功能构成的实现 |
| `src/utils` | 工具方法 |
| `tsconfig.json` | TypeScript 编译配置 |

标准文件定义见 [package.json](https://docs.npmjs.com/cli/v10/configuring-npm/package-json) 和 [tsconfig.json](https://www.typescriptlang.org/docs/handbook/tsconfig-json.html#handbook-content)。

<a id="db160213"></a>

### plugin.config.json

该文件连接后台插件身份、功能构成和插件代码。

| 配置项 | 说明 |
| --- | --- |
| `siteDomain` | 创建插件的站点地址；私有化环境需与实际部署一致 |
| `pluginId` | 后台插件 ID |
| `pluginSecret` | 插件密钥；使用下文的 `lpm config` 管理，仅供 LPM 使用 |
| `resources` | 资源列表；每项将后台 ResourceId 映射到一个插件入口文件 |

`pluginSecret` 应通过 `lpm config set` 写入，不要手工把明文填入配置文件。LPM 要求使用其管理的加密配置，因此审查时不能仅凭 `plugin.config.json` 存在该字段或一段长字符串，就认定仓库提交了明文 Secret；还需检查客户端源码是否定义、读取或发送实际密钥，并检查构建产物是否包含它。

只依赖 JSSDK、宿主上下文和客户端交互的纯前端插件不需要运行时 Secret。此时 `pluginSecret` 仅服务于本地 LPM 生命周期，不应被应用代码 import。需要换取平台凭证或调用 OpenAPI 时，应由自有服务端保存 Secret 和平台 token；把 Secret 放入前端环境变量仍会进入可读取的客户端产物，不能形成安全边界。

<a id="table-content-1"></a>

### resources：资源与入口映射

| 字段 | 说明 |
| --- | --- |
| `id` | 后台功能构成中的 ResourceId；同一插件内必须唯一 |
| `entry` | 对应前端代码的入口路径 |

以下是 `resources` 属性的值，不是完整配置文件。开发工具分别从两个入口打包，产物对应 `page_web` 和 `page_mobile`。

```json
[
  {
    "id": "page_web",
    "entry": "./src/features/page/web/index.tsx"
  },
  {
    "id": "page_mobile",
    "entry": "./src/features/page/mobile/index.tsx"
  }
]
```

ResourceId 重复会导致调试或发布失败。入口名称可以按工程组织，但 `id` 必须与开发者后台配置对应。

## 修改配置与同步新增构成

在**插件工程根目录**执行 `lpm config`。本篇定义可操作的 key 为 `pluginId`、`pluginSecret`、`siteDomain`。

```text
lpm config set <key> <value>
lpm config get <key>
```

例如更新插件密钥时，将占位值替换为实际密钥：

```sh
lpm config set pluginSecret REPLACE_WITH_PLUGIN_SECRET
```

LPM 不提供把任意环境变量自动映射到 `plugin.config.json` 的通用机制。需要在本地或 CI 从密钥管理系统注入时，由外层脚本读取 Secret 并调用 `lpm config set`；脚本不得打印参数，执行后也要检查日志和产物不含明文。业务环境配置应由应用自己的构建或运行配置管理，不要与 LPM 的插件身份配置混用。

初始化后若在后台新增了插件构成，可同步到当前工程：

```sh
lpm update
```

该命令会把新增构成写入 `plugin.config.json` 并初始化入口代码。同步后检查资源映射和生成的入口，再合并已有入口中的自定义修改。
