# `lpm` 生命周期

在需要检查或变更飞书项目托管插件配置、申请 scope、同步构成、本地调试、构建上传、预览或发布时读取。`lpm` 是插件工程和托管配置的操作入口；点位、接口和权限的精确契约仍应先用本 skill 的本地 CLI 查询。

## 使用边界

- 使用 `lpm --cwd <plugin-root> ...`，其中 `<plugin-root>` 必须来自目标工程或用户提供的路径。
- 用户请求范围内的只读检查可以直接执行。不要用直接 HTTP 或浏览器操作绕过 `lpm` 的托管配置流程。
- `pluginSecret`、平台 token、授权码和刷新凭证不得出现在命令记录、日志、fixture、Git、CI 输出或客户端代码中。

## 生命周期状态

| 目标 | 先读取 |
| --- | --- |
| 安装、登录、初始化和配置同步 | [CLI 开发实践](<../docs/plugin/cli/飞书项目开发工具 CLI 开发实践.md>) |
| 新增或修改插件构成 | [添加插件功能](../docs/plugin/guides/添加插件功能.md) |
| 本地调试和客户端排错 | [开发调试客户端](../docs/plugin/client/开发调试客户端.md) |
| 构建并上传客户端产物 | [发布插件产物](../docs/plugin/client/发布插件产物.md) |
| 创建插件版本、申请发布和安装验证 | [发布插件](../docs/plugin/guides/发布插件.md) |

`lpm update` 只同步已在控制台新增的构成；执行前检查本地改动和 `plugin.config.json` 的资源映射。构建或上传产物不等于创建插件版本、发布成功或目标空间已经安装新版本。

## 远端变更

在每次远端变更前，先取得完整远端基线，准备完整替换内容并检查 diff；明确列出新增、修改和将删除的项。不得绕过 CLI 的删除保护。

远端写入、删除、scope、元数据、点位或资源配置变更，以及发布，都需要分别说明具体命令和影响，并在紧邻实际变更时取得明确确认。上传构建产物不构成发布授权。

完成时清晰区分已完成的本地构建、上传、预览、发布和安装验证，不能把前一阶段推断为后一阶段已经完成。

## `lpm ai docs`

仅在本地资料未覆盖，或用户明确要求核对当前官方内容时使用。把结果作为补充或时效核验的证据：核对标题和官方 URL，并保留仍待真实宿主验证的条件。

不要把缺失信息、模糊检索结果或 AI 推断写成平台事实；也不能用它静默改写本地已确认的契约。它不替代本地 capability 页面、fixture 或真实宿主验证。
