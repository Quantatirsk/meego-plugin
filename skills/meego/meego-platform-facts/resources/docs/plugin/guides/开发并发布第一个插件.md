本篇以一个读取第三方选项、更新工作项描述的选择器为例，串起插件创建、构成配置、客户端开发、后端联调和企业内发布。示例使用官方 `v2/quickstart` 前端与 Java 服务端工程；其中的工程结构和命令按 2026-09-04 文档快照说明，不作为所有工程的固定模板。

<a id="b65e56fd"></a>

## 示例目标与数据流

选择器从第三方系统取得选项；用户选择后，客户端请求自建后端，由后端更新工作项描述，并在页面展示更新时间。

![选择器与后端数据交互时序](<../assets/6dabf821895d97087b2701d3.png>)

客户端通过宿主 JSSDK 获取点位信息，自建后端负责示例业务接口和平台 OpenAPI 调用。这三个接口层次应分开理解。

## 前提条件

- 完成[环境准备](<环境准备.md>)，具备所选客户端与服务端技术栈的开发环境。
- 本例需要后端资源和可访问域名；不涉及后端的插件无需为复用教程而创建服务端。
- 准备测试空间和可配置页面布局的账号，用于调试权限与构成展示。

## 1. 创建插件

从飞书项目工作台用户头像菜单进入开放平台，选择“新建插件”，填写名称与图标。随后在基本信息页补充短描述、分类、详情、封面、帮助文档和协作人，详见[创建插件](<创建插件.md>)。

![插件基本信息](<../assets/e1d5fbb6010bd8309371cd71.png>)

`Plugin ID` 与 `Plugin Secret` 是插件访问凭证相关信息；后者用于服务端鉴权，不填入公开客户端代码。

<a id="6f5c4d37"></a>

### 配置权限与调试空间

本例需要读取工作项并更新描述，因此申请“更新工作项实例数据”“获取工作项实例信息”等实际接口权限。在权限管理中设置测试数据范围，原例使用“文档演示空间”，再选择所需接口并批量获取权限。

![调试范围与接口权限](<../assets/72dd60bd5f73bc4e98cb5109.png>)

调试范围用于开发阶段的测试授权；原例提到虚拟 `plugin_token`，它的用途和限制按[权限管理](<../../openapi/guides/权限管理.md>)与[获取访问凭证](<../../openapi/guides/获取访问凭证.md>)处理，不能用作正式安装授权的替代。没有 OpenAPI 交互时可跳过这一步的接口权限申请。

## 2. 添加构成并初始化工程

在“插件功能”中添加“表单页控件”，选择工作项类型和适用端。本例选择全部工作项类型、网页端，其他构成见[添加插件功能](<添加插件功能.md>)。

![添加表单页控件](<../assets/b8cadf54a19605adf8916f71.gif>)

| 配置 | 含义 | 本例 |
| --- | --- | --- |
| 名称 | 控件显示名称 | 选择器 |
| 描述 | 说明该控件实现的功能 | 用于实现选择器功能 |
| Key | 系统生成的构成标识，不可修改 | 使用实际生成值 |
| 工作项类型 | 全部或指定类型，包括需求、缺陷、版本、迭代及其他类型 | 全部 |
| 适用端 | 控件运行端，对应端代码分别维护 | 网页端 |
| ResourceId | 客户端资源标识，必须与工程配置对应 | `control_web_9ug7q7` |

原配置表将控件描述误写为“详情标签页”，本文按本例的表单控件修正。各点位是否支持移动端以[控件 Control](<../points/控件 Control.md>)为准。

<a id="645c5615"></a>

### 初始化并核对资源

1. 在插件功能页复制平台生成的初始化命令。
2. 在终端执行并按提示输入工程名称，原例为 `quick-start`。
3. 打开工程，检查 `plugin.config.json` 的 `resources` 中 `id` 与平台 ResourceId 一致。

初始化通常写入对应 ResourceId；发现不一致时用平台实际值修正。不要把本页的示例 ID 用于自己的插件。

### 启动开发服务

原示例工程使用以下命令：

```sh
lpm start
```

编译成功并输出本地开发服务地址后，再到平台查看效果。原页的终端日志包含被 OCR 或排版破坏的字符，且误标为 JSON；这里保留需要观察的结果，不提供伪造的固定日志或端口。

CLI 不同代际的命令请对照[CLI 介绍](<../cli/飞书项目开发工具 CLI 介绍.md>)及实际 `lpm --help`；本段记录原示例工程的启动方式。

### 配置后端域名

本例需要后端通信，将 `App.tsx`、`login.ts` 中的 `https://www.example.com` 替换为实际服务地址。无需后端的插件可跳过。

### 示例业务接口

下列两个路径属于自建示例服务，不是飞书项目 OpenAPI 路径。

| 路径 | 职责 |
| --- | --- |
| `/getDemoList` | 模拟从第三方系统获取选择器业务数据 |
| `/updateDescription` | 接收客户端选中值，在服务端调用平台接口更新工作项描述 |

`/getDemoList` 的两条演示记录如下。姓名和城市使用等义 Unicode 转义，字段、数值和原例语义不变；去掉了 JSON 不支持的注释和尾部省略号。

```json
[
  { "id": 1, "name": "\u5f20\u4e09", "age": 23, "city": "\u5317\u4eac" },
  { "id": 2, "name": "\u674e\u56db", "age": 24, "city": "\u4e0a\u6d77" }
]
```

`/updateDescription` 请求示例如下。`project_key` 和数值 ID 是需要替换的演示值，`story` 保留原例的需求类型值，实际类型以当前空间为准。

```json
{
  "project_key": "example_space",
  "work_item_type_key": "story",
  "work_item_id": 123456,
  "value": "Updated description"
}
```

| 字段 | 含义 |
| --- | --- |
| `project_key` | 空间 key |
| `work_item_type_key` | 工作项类型 key |
| `work_item_id` | 工作项实例 ID |
| `value` | 要写入描述字段的内容 |

### 跨域处理

客户端由平台页面加载，请求自建后端时需由后端允许相应来源。原示例提供下面的 Spring MVC 配置；它允许所有来源的 GET、POST、DELETE 请求，不是生产环境的来源白名单。

```java
import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class WebMvcConfiguration implements WebMvcConfigurer {
    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")
            .allowedOrigins("*")
            .allowedMethods("GET", "POST", "DELETE")
            .allowedHeaders("*");
    }
}
```

实际服务应按部署页面的真实 Origin 和鉴权方式配置。CORS 只控制浏览器跨域访问，不承担请求身份认证。

原 Java 工程使用 Maven 打包，再启动生成的 JAR。这里保留原例 JAR 名，实际执行时按构建结果替换。

## 5. 联调与测试

在实际控件展示页面验证两项结果：选择器收到后端数据并展示人员选项；选中后描述字段按预期更新，且更新时间可见。应同时确认失败请求和鉴权异常能被定位。

不涉及后端的插件可以省略本例的数据联调，但仍需验证自己的客户端功能、点位和适用端。原文“可跳过测试”已收窄为跳过不适用的后端联调。

## 6. 上传产物并发布插件

测试完成后退出本地调试进程。原示例工程使用下列命令构建并上传客户端产物：

```sh
lpm release
```

确认构建和上传均成功，并记录返回的产物版本号。该版本号与插件发布版本号不同；上传成功不等于插件版本已发布。新 CLI 的对应流程见[CLI 开发实践](<../cli/飞书项目开发工具 CLI 开发实践.md>)。

### 创建企业内插件版本

在开放平台插件详情进入“管理 > 插件发布”，创建版本并选择刚上传的客户端产物。

![创建插件版本](<../assets/5dcb2e2e2ee46f981ed95d74.png>)

| 配置 | 作用 | 本例 |
| --- | --- | --- |
| 版本号 | 插件发布版本 | `1.0.0` |
| 版本描述 | 说明本次功能和变更 | 创建一个选择器 |
| 产物版本 | 选择已上传的客户端构建产物 | `1`，以实际结果为准 |
| 插件使用范围 | 企业内部或共享到插件商店 | 企业内部使用 |
| 企业内商店可见范围 | 全部空间、指定空间或不在商店显示 | 租户内所有空间可见 |

企业内使用限定当前租户。共享到插件商店涉及市场插件的审批和分发，按[发布插件](<发布插件.md>)处理，不能仅修改可见范围就绕过审批。本例完成配置后申请发布。

## 发布后验证

1. 空间管理员在“空间配置 > 插件管理”中添加插件，在允许的商店可见范围内搜索名称并安装。
2. 在授权工作项类型的页面布局中加入选择器。
3. 打开适用工作项，验证已发布版本的显示和数据更新。

![安装并验证插件](<../assets/f1c246c667d79c7c8f9f4e4d.gif>)

“不在商店显示”的插件不能按搜索商店的路径验证，应使用对应发布范围支持的安装方式，详见发布文档。
