本篇统一插件开发中常见的平台概念与客户端、OpenAPI 标识。名称相近的字段不应仅凭名称互换；调用时使用目标 JSSDK 方法或 OpenAPI 参数表要求的字段。

<a id="762eec2e"></a>

## 平台对象与标识

| 业务对象 | 含义 | 常见标识 |
| --- | --- | --- |
| 空间 | 团队协作的基本单元，可以管理一个或多个项目 | OpenAPI 使用 `project_key`；客户端上下文和部分 JSSDK 方法使用 `spaceId`；空间 URL 的短名为 `simple_name` |
| 工作项类型 | 空间内定义的事项类别，例如需求、缺陷、版本或迭代 | OpenAPI 常用 `work_item_type_key`；客户端上下文和方法常用 `workObjectId` |
| 工作项实例 | 用户实际创建的一条工作项数据 | OpenAPI 常用 `work_item_id`；客户端方法常用 `workItemId` |
| 字段 | 工作项属性的定义 | `field_key` 是系统字段标识，`field_alias` 是可约定的对接标识，`field_type_key` 说明字段类型 |
| 流程模板 | 工作项生命周期的节点流或状态流定义 | `template_id` |
| 节点 | 流程中的可执行步骤 | `node_id` |
| 角色和人员 | 空间中承担职责的人员关系 | `role_owners`、`user_key`、`node_owners`、`role_assignee` |

官方术语页将 `project_key` 与 `spaceId` 归为同一空间标识体系。两者在不同接口中的格式和位置以各自契约为准，不能把客户端参数名直接替换到 OpenAPI 路径或请求体中。

## 字段和状态

| 概念 | 用途 | 注意事项 |
| --- | --- | --- |
| `field_key` | 定位空间中的字段定义 | 写入值的结构由字段类型决定 |
| `field_alias` | 跨空间约定的对接名称 | 是否可用于某个接口取决于该接口的参数定义 |
| `field_type_key` | 标识单选、多选、人员、富文本等字段类型 | 不同类型对应不同 value 结构 |
| `work_item_status` | 当前工作项状态 | 状态枚举可由空间管理员配置，不能硬编码展示名称 |
| `node_schedule` | 节点估分或排期数据 | 节点排期和工作项字段是不同模型 |

字段值格式见[字段与属性解析格式](<../../openapi/formats/字段与属性解析格式.md>)，客户端类型定义见[通用类型定义](<../jssdk/通用类型定义.md>)。

## 开发时的对照原则

1. 从当前插件点位取得 `spaceId`、`workObjectId`、`workItemId` 等客户端上下文。
2. 调用 OpenAPI 时按接口参数表映射为 `project_key`、`work_item_type_key`、`work_item_id` 等服务端字段。
3. 用 `field_key` 确定字段，再按照字段类型和接口定义构造值。
4. 处理人员相关数据时区分 `user_key` 和飞书侧其他人员 ID，不能根据展示名称匹配。
