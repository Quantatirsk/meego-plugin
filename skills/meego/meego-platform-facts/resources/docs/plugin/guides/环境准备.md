飞书项目插件由客户端资源、平台点位配置和可选的自有服务端组成。开始前应先区分三类运行环境：本地 Node.js 工具链、飞书项目网页或移动端宿主，以及处理 OpenAPI 的自有服务端。

<a id="c8a8db85"></a>

<a id="53942104"></a>

## 客户端工具链

客户端开发需要基本的 JavaScript、HTML、CSS 和 React 构建经验，并需理解异步加载与错误处理。

<a id="b609c8ca"></a>

### Node.js 与包管理

官方环境页要求 Node.js 高于 16。新插件工程应优先遵循自身 `package.json` 与锁文件的约束，不能把来源页面中的推荐版本视为当前 CLI 的唯一要求。

<a id="eb66f1cd"></a>

### 飞书项目开发工具

安装官方 CLI 后检查命令是否可用：

```sh
npm install --global @lark-project/cli@latest
lpm --version
```

CLI 用于初始化、调试、构建和上传客户端产物。它不部署自有后端，也不替代本地项目的依赖管理。CLI 的登录与工程操作见官方[开发工具说明](<../cli/飞书项目开发工具 CLI 介绍.md>)。

<a id="9969c42f"></a>

## 浏览器

- 网页端调试需要受支持的现代浏览器；官方页列举 Chrome 和 Edge。

<a id="3a8e10a4"></a>

## 移动端

- 移动端需安装飞书。是否可用以目标 JSSDK 方法的移动端版本矩阵为准，不能因为一个 API 从 V7.35.0 开始支持，就推导其他 API 同样支持。
- 插件运行在宿主沙箱中。下载、弹窗、打印、存储和本地网络访问等限制应在开发前查看[客户端开发限制](<../client/客户端开发限制.md>)。

插件入口先注入 React 与 ReactDOM 的共享模块，再动态加载 App；使用宿主组件库时不能把组件放在入口的静态导入中。具体顺序见[客户端组件库接入](<../components/客户端组件库接入.md>)和[shared](<../jssdk/shared.md>)。

<a id="38dff170"></a>

## 服务端基础

插件自有服务端没有固定语言限制。它通常负责：

- 以插件凭证调用 OpenAPI。
- 用客户端授权码交换用户凭证。
- 接收并校验事件回调。
- 保存不应留在客户端本地存储中的业务数据和密钥。

OpenAPI 的认证、SDK 和事件协议应查阅已有的[飞书项目 OpenAPI 文档](<../../openapi/README.md>)。SDK 的当前快照版本、运行时要求和仓库配置见[服务端 SDK](<../../openapi/guides/服务端SDK.md>)。

<a id="a8d03d19"></a>

### Go SDK

使用 Go 自建服务时，以[服务端 SDK](<../../openapi/guides/服务端SDK.md>) 中的当前包名和认证方式为准；不复制来源页中会过时的版本号。

<a id="434b177a"></a>

### Java SDK

使用 Java 自建服务时，仍以[服务端 SDK](<../../openapi/guides/服务端SDK.md>) 和目标项目的依赖管理为准。来源页的开放 CORS 示例不应直接用于生产。

来源页面给出了 Java 服务端的 `allowedOrigins("*")` 示例。它不适合作为通用生产配置：自有服务端应依据实际前端来源、认证方式和业务接口设置明确的 CORS 策略。

## 开始前检查

1. 确认 Node.js、包管理器和 `lpm` 可运行。
2. 确认已创建插件并取得开发权限；客户端资源还需要对应的 `resourceId` 配置。
3. 确认插件所需 OpenAPI 权限、目标空间安装状态和操作用户权限。
4. 按目标端验证点位、JSSDK API 和组件库支持范围。
5. 需要本地服务时，先验证浏览器、宿主 iframe 和服务端之间的网络及 CORS 边界。
