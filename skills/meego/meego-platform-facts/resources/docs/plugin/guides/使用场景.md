# 使用场景

本页不按行业或外部系统划分，而是按飞书项目中的扩展目标选择插件能力。先确定功能需要出现的位置、是否读写平台数据、是否需要服务端，再进入对应点位或 OpenAPI 文档。

## 按扩展目标选择能力

| 目标 | 优先选择 | 是否需要客户端 | 是否需要服务端 | 继续阅读 |
| --- | --- | --- | --- | --- |
| 在工作项详情中展示或编辑内容 | 详情标签页、表单页控件、节点表单控件或实例更多按钮 | 是 | 仅在需要 OpenAPI、自有数据或敏感操作时需要 | [Tab](<../points/详情标签页 Tab.md>)、[Control](<../points/控件 Control.md>)、[Button](<../points/按钮 Button.md>) |
| 在空间中提供完整页面或自定义视图 | 导航功能页、视图模式或轻应用组件 | 是 | 按数据来源和写入需求决定 | [Page](<../points/导航功能页 Page.md>)、[View](<../points/视图模式 View.md>)、[轻应用组件](<../points/轻应用组件 LiteAppComponent.md>) |
| 在表格或字段位置提供专用数据形态 | 表格列控件、字段类型或节点排期 | 是 | 按点位协议和数据来源决定 | [表格列](<../client/表格列搭建工具.md>)、[字段类型](<../points/扩展字段-字段类型 CustomField.md>)、[节点排期](<../points/扩展字段-节点排期 Schedule.md>) |
| 提供空间级设置 | 插件配置 | 是 | 常见，但不是必需 | [Configuration](<../points/插件配置 Configuration.md>) |
| 在平台数据变化后处理请求 | 监听事件 | 否 | 是 | [监听事件](<../../openapi/events/监听事件.md>) |
| 在平台操作前决定是否允许或干预 | 拦截事件 | 可选 | 是 | [Intercept](<../points/拦截事件 Intercept.md>) |
| 在自动化规则中提供触发器或操作 | 自动化连接器 | 否 | 是 | [Connector](<../points/自动化连接器 Connector.md>) |

同一个插件可以组合多个构成，但每个客户端构成都应有明确的 ResourceId 和入口文件。新增或删除构成会改变平台配置，不能只新增前端代码而不在“插件功能”中完成配置。

## 选择客户端与服务端形态

| 形态 | 适用条件 | 主要边界 |
| --- | --- | --- |
| 客户端插件 | 功能只依赖 JSSDK、宿主上下文和客户端交互 | 只使用点位支持的 JSSDK 方法；分别验证网页和移动端 |
| 客户端加服务端 | 界面需要读写 OpenAPI、访问受控数据或执行长耗时操作 | 客户端调用自有服务；服务端调用 OpenAPI 并保管凭证 |
| 仅服务端 | 只处理事件、拦截或自动化请求 | 使用公开可访问的服务端回调地址，完成鉴权、超时和重试处理 |

不要让浏览器直接交换或保存平台访问凭证。客户端需要代表用户操作时，先通过 JSSDK 获取一次性授权码，再发送给自有服务端换取用户凭证；完整流程见[获取访问凭证](<../../openapi/guides/获取访问凭证.md>)。

## 开始前的四项判断

1. **入口**：功能应出现在哪个页面、操作或自动化环节？该点位是否支持目标端？
2. **资源**：是否需要网页和移动端分别配置 ResourceId 与入口？
3. **数据**：需要的客户端 API、OpenAPI 和字段元数据分别是什么？先查具体接口契约。
4. **信任边界**：是否需要 Plugin Secret、用户授权、事件回调或受保护数据？只要答案为是，就需要服务端边界。

功能形态确定后，按[开发并发布第一个插件](<开发并发布第一个插件.md>)完成初始化、调试、发布和安装验证。
