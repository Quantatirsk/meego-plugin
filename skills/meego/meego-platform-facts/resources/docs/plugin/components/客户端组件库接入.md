飞书项目客户端组件库是宿主在插件运行时提供的注入资源，包含基础组件及 `UserSelect`、`WorkItemFinder` 等业务组件。它不等同于普通前端运行时依赖：本地安装的包用于 TypeScript 类型提示，组件实例仍由插件宿主提供。

本篇与 [shared](<../jssdk/shared.md>)配套阅读。组件的点位范围和上下文来源见 [Context](<../jssdk/Context.md>)。

<a id="7268b941"></a>

## 使用边界

- 组件类型包使用 `@lark-project/ui-kit-plugin`，建议作为开发依赖安装。
- 网页端从 `@lark-project/ui-kit-plugin` 导入；移动端从 `@lark-project/ui-kit-plugin/mobile` 导入。
- 只能使用这两个公开入口。深层路径如 `@lark-project/ui-kit-plugin/xxx` 可能得到 `undefined`，内部类型路径也不保证稳定。
- 组件代码必须位于动态加载的 App 内，且 App 的加载发生在 `setSharedModules` 完成之后。入口文件的静态导入会先执行，不能在入口直接导入组件库。

## 安装类型包

```sh
npm install --save-dev @lark-project/ui-kit-plugin@latest
```

安装后可按目标端导入类型和组件符号：

```ts
import { UserSelect } from '@lark-project/ui-kit-plugin';
import { WorkItemFinder } from '@lark-project/ui-kit-plugin/mobile';
```

上例展示两个端的入口，单个资源只应选择其实际运行端支持的入口。具体组件的 Web 和移动端支持情况以各组件文档为准。

<a id="07313549"></a>

## 正确的加载顺序

入口只负责把 React 与 ReactDOM 注入给宿主，并在注入成功后动态加载 App。这样 App 内对组件库的静态导入才会在运行时可用。

<a id="b90170bd"></a>

### 完整入口示例

```tsx
import React, { lazy, Suspense } from 'react';
import ReactDOM from 'react-dom';
import { createRoot } from 'react-dom/client';

const App = lazy(() => import('./App'));

export default async function main() {
  await window.JSSDK.shared.setSharedModules({
    React,
    ReactDOM,
  });

  const container = document.createElement('div');
  container.id = 'app';
  document.body.appendChild(container);

  createRoot(container).render(
    <Suspense fallback={<div>Loading...</div>}>
      <App />
    </Suspense>,
  );
}
```

以下是动态 App 内消费 `WorkItemFinder` 的最小示例。`spaceId` 与 `workObjectId` 应从当前点位上下文读取，不能写死为其他空间的标识。

```tsx
import { useState } from 'react';
import { WorkItemFinder } from '@lark-project/ui-kit-plugin';

type Props = {
  spaceId: string;
  workObjectId: string;
};

export default function App({ spaceId, workObjectId }: Props) {
  const [searchId, setSearchId] = useState<string>();

  return (
    <WorkItemFinder
      spaceId={spaceId}
      workObjectId={workObjectId}
      searchId={searchId}
      onSubmit={value => setSearchId(value.searchId)}
    />
  );
}
```

## 常见失效原因

| 现象 | 原因 | 处理方式 |
| --- | --- | --- |
| 组件为 `undefined` | 使用了未公开的深层导入路径，或 App 在共享模块注入前已被求值 | 仅用 Web 或移动端公开入口，并保持动态加载顺序 |
| 本地类型可用，宿主中组件不可用 | 只安装了类型包，未完成宿主共享模块注入 | 在资源入口执行 `await window.JSSDK.shared.setSharedModules(...)` |
| 同一组件在移动端失效 | 该组件没有对应移动端实现或导入路径不匹配 | 查阅目标组件的端支持矩阵，再选择 Web 或 `/mobile` 入口 |
| 查询范围不正确 | 没有使用当前点位的空间和工作项类型上下文 | 通过当前点位 API 获取 `spaceId` 和 `workObjectId` |
