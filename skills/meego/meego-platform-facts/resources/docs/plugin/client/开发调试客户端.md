# 开发调试客户端

完成[初始化插件工程](<初始化插件工程.md>)后，在插件工程根目录启动本地调试服务，再分别从网页端或飞书移动端进入调试态。调试加载本地产物；正式用户使用的产物仍需走[构建上传与发布流程](<发布插件产物.md>)。

<a id="c089b710"></a>

## 启动调试服务

在包含 `plugin.config.json` 的插件工程根目录执行：

```sh
lpm start
```

该命令用于调试和预览网页端、移动端的插件构成。若出现以下错误，应先检查 `plugin.config.json` 的资源配置和后台构成对应关系：

```text
No resources need to build, please check the plugin.config.json / developer platform and retry.
```

核对 `resources[].id` 是否对应后台 ResourceId、`entry` 是否指向实际入口，以及是否已同步新增构成。配置与 `lpm update` 用法见[资源与入口映射](<初始化插件工程.md#table-content-1>)。

<a id="4022e57f"></a>

## 网页端调试

1. 保持本地 `lpm start` 运行。
2. 在开发者后台勾选“开启本地调试”。
3. 打开飞书项目空间，刷新当前页面，进入对应构成查看效果。

<a id="e64089ac"></a>

## 移动端调试

| 条件 | 要求 |
| --- | --- |
| 飞书移动端版本 | 建议 7.35 或更高；具体能力以各 API 的支持说明为准 |
| 网络 | 开发机与手机 Wi-Fi 必须处于同一局域网 |
| 登录身份 | 手机登录账号必须拥有当前插件的开发权限 |

以上是进入移动调试的基础条件，具体 JSSDK 或组件能力可能要求更高版本，应另查各自支持表。

1. 启动工程后，找到终端输出的二维码。
2. 在飞书移动端使用“扫一扫”扫描该二维码。
3. 进入飞书项目界面，调试对应移动端构成。

退出飞书应用后，调试状态默认退出，需要重新扫码。需要查看日志或异常时，可在插件中自行引用 [vConsole](https://www.npmjs.com/package/vconsole)；它是可选调试工具，不是 SDK 必需依赖。

## 连接配置、入口和页面

### 1. 确认插件配置

`pluginId`、`pluginSecret` 和 `siteDomain` 应由初始化及 `lpm config` 管理，密钥变更规则见[修改插件配置](<初始化插件工程.md#65644d0f>)。`plugin.config.json` 是 LPM 的配置输入，前端入口不得读取或打包其中的 `pluginSecret`。下方为结构示例，所有占位身份信息必须对应真实后台插件。

```json
{
  "siteDomain": "https://project.feishu.cn",
  "pluginId": "MII_REPLACE_WITH_PLUGIN_ID",
  "pluginSecret": "REPLACE_WITH_PLUGIN_SECRET",
  "resources": [
    {
      "id": "REPLACE_WITH_RESOURCE_ID",
      "entry": "./src/features/board_web/index.tsx"
    }
  ]
}
```

`resources[].id` 是后台构成的 ResourceId，配置文件并不存在本例所需的顶层 `resourceId` 字段。`board_web` 只是示例目录名，不能单凭目录名决定点位类型。

### 2. 编写资源入口

在 `entry` 指定的 `src/features/board_web/index.tsx` 中初始化共享模块并挂载应用。ReactDOM 版本需支持 `createRoot`，工程需具备 JSX 构建配置。

```tsx
import React, { lazy, Suspense } from "react";
import ReactDOM from "react-dom";
import { createRoot } from "react-dom/client";

const App = lazy(() => import("./App"));

export default async function main() {
  await window.JSSDK.shared.setSharedModules({
    React,
    ReactDOM,
  });

  const container = document.createElement("div");
  container.id = "app";
  document.body.appendChild(container);

  const root = createRoot(container);
  root.render(
    <Suspense fallback={<div>Loading...</div>}>
      <App />
    </Suspense>,
  );
}
```

必须等待共享模块初始化后，再加载消费注入资源的模块。`lazy` 用法和注入时序见 [shared](<../jssdk/shared.md>)，组件接入见[客户端组件库接入](<../components/客户端组件库接入.md>)。

### 3. 编写页面组件

在同目录 `App.tsx` 中导出页面组件。下面以 `window.JSSDK.navigation.open` 展示客户端导航调用。

```tsx
import React from "react";

const resources = [
  {
    label: "Get Started",
    url: "https://project.feishu.cn/openapp/start_guide",
  },
  {
    label: "Client API",
    url: "https://project.feishu.cn/b/helpcenter/1p8d7djs/x4l57qtx",
  },
  {
    label: "Client Components",
    url: "https://project.feishu.cn/b/helpcenter/1p8d7djs/aa6btca8",
  },
];

export default function App() {
  return (
    <main>
      <h1>Quick Start</h1>
      <p>
        Edit <code>src/features/board_web/App.tsx</code> to get started.
      </p>
      <nav aria-label="Developer resources">
        {resources.map(({ label, url }) => (
          <button
            key={url}
            type="button"
            onClick={() => window.JSSDK.navigation.open(url)}
          >
            {label}
          </button>
        ))}
      </nav>
    </main>
  );
}
```

页面结构可按产品需要替换。导航端支持与参数见 [navigation](<../jssdk/navigation.md>)。
