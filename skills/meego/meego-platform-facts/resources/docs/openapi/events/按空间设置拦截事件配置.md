# 按空间设置拦截事件配置

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-intercept-project-intercept-config-create"></a>
- **按空间设置拦截事件配置** ｜ `openapi.post.open-api-intercept-project-intercept-config-create` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

按空间缩小插件拦截事件的范围，可进一步限定工作项类型、流程模板、节点、字段或状态流转。此接口无需单独开通接口权限；请求仍需携带通用鉴权 Header。

写入后约 **5 分钟**生效。一次“工作项类型 × 事件类型”组合只能配置一条规则，且范围不能超出开发者后台已经配置的范围。

<a id="请求说明"></a>

## 接口与配置边界

| 项目 | 值 |
| --- | --- |
| 方法 | `POST` |
| 路径 | `/open_api/intercept/project_intercept_config/create` |
| Header | [通用请求头](../guides/OpenAPI概述.md#a8e43b86) |
| 查询配置 | [查询拦截事件配置](查询拦截事件配置.md) |
| 事件定义 | [拦截事件](拦截事件.md) |

`disable_intercept: true` 表示当前空间的所有事件都不再拦截，不再向开发者发送拦截请求。清空精细化配置则恢复到开发者后台配置的事件范围，与禁用拦截含义不同。

## 请求参数

### 请求体

| 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- |
| `project_key` | string | 必填 | 飞书项目空间 key |
| `disable_intercept` | boolean | 可选 | 是否禁用当前空间的全部拦截 |
| `project_intercept_config` | `list<object>` | 设置范围时必填 | 精细化配置列表；禁用与清空操作省略 |

### project_intercept_config[]：一组事件范围

以下字段均在原文中标为可选。结构参见 [project_intercept_config](../formats/数据结构汇总.md#238b9eee)。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `events` | `list<int64>` | 事件编号列表，建议同一组内配置同类事件 |
| `work_item_type` | `list<string>` | 工作项类型 key；示例注释还允许对接标识 |
| `work_item_intercept_config` | `list<object>` | 按工作项类型进一步限定范围 |
| `project_intercept_config_id` | string | 拦截配置 ID；原文未说明传入时是更新、替换还是新增 |

### work_item_intercept_config[]：类型内的细化条件

以下字段均为可选。完整结构参见 [work_item_intercept_config](../formats/数据结构汇总.md#fd963053)。

| 字段 | 类型 | 作用范围 |
| --- | --- | --- |
| `work_item_type` | string | 当前细化规则对应的工作项类型 |
| `fields` | `list<string>` | 仅用于修改字段 `1009`、批量修改字段 `1010`，需同时匹配 `events` |
| `template_ids` | `list<string>` | 流程模板列表，用于模板升级 `1006/1007`，及本页具体场景所示的创建 `1001`、计划表 `1011/1012` |
| `node_intercept_config` | `list<object>` | 节点事件 `2001–2007`、子任务事件 `4001–4008` 的模板与节点范围 |
| `state_intercept_config` | `list<object>` | 状态流转事件 `3001` 的模板与流转范围 |

### 节点与状态条件

| 对象 | 字段 | 类型 | 必填性 | 说明 |
| --- | --- | --- | --- | --- |
| `node_intercept_config[]` | `template_id` | string | 可选 | 节点模板 ID |
| `node_intercept_config[]` | `node_ids` | `list<string>` | 可选 | 要拦截的节点 ID 列表 |
| `state_intercept_config[]` | `template_id` | string | 可选 | 状态模板 ID |
| `state_intercept_config[]` | `transition_ids` | `list<string>` | 可选 | 要拦截的流转 ID 列表 |

节点及子任务事件只识别 `node_intercept_config[].template_id`，会忽略其他位置的模板 ID。状态事件同理，只识别 `state_intercept_config[].template_id`。计划表事件目前最细到模板粒度，不支持按节点或子任务细分。

## 基础配置示例

### 通用嵌套结构

本例将节点负责人修改事件 `2006` 限定到模板 `224744` 的 `start` 节点。每组只配置与其事件匹配的细化条件。

```json
{
  "project_key": "{{project_key}}",
  "disable_intercept": false,
  "project_intercept_config": [
    {
      "events": [
        2006
      ],
      "work_item_type": [
        "story"
      ],
      "work_item_intercept_config": [
        {
          "work_item_type": "story",
          "node_intercept_config": [
            {
              "template_id": "224744",
              "node_ids": ["start"]
            }
          ]
        }
      ]
    }
  ]
}
```

### 仅拦截需求创建

只配置 `1001` 和 `story` 即可。

```json
{
  "project_key": "{{project_key}}",
  "disable_intercept": false,
  "project_intercept_config": [
    {
      "events": [
        1001
      ],
      "work_item_type": [
        "story"
      ]
    }
  ]
}
```

### 禁用当前空间的全部拦截

```json
{
  "project_key": "{{project_key}}",
  "disable_intercept": true
}
```

### 清空精细化范围，恢复后台配置

```json
{
  "project_key": "{{project_key}}",
  "disable_intercept": false
}
```

以上禁用与清空操作都省略 `project_intercept_config`，以对应操作示例为准。

## 子任务与计划表

### 按模板拦截子任务创建

子任务属于节点，因此模板 ID 放在 `node_intercept_config` 中。本例针对模板 `224736` 下的 `story`。

```json
{
  "project_key": "{{project_key}}",
  "project_intercept_config": [
    {
      "events": [
        4001
      ],
      "work_item_type": [
        "story"
      ],
      "work_item_intercept_config": [
        {
          "work_item_type": "story",
          "node_intercept_config": [
            {
              "template_id": "224736"
            }
          ]
        }
      ]
    }
  ]
}
```

### 按模板和节点拦截子任务事件

规则分别限定模板 `224736` 的 `start` 节点、模板 `224744` 的 `end` 节点。原文描述只说“创建”，但示例同时订阅 `4001` 和 `4002`，应按这两个事件编号的实际定义理解；多余的孤立斜杠已移除。

```json
{
  "project_key": "{{project_key}}",
  "project_intercept_config": [
    {
      "events": [
        4001,
        4002
      ],
      "work_item_type": [
        "story"
      ],
      "work_item_intercept_config": [
        {
          "work_item_type": "story",
          "node_intercept_config": [
            {
              "template_id": "224736",
              "node_ids": [
                "start"
              ]
            },
            {
              "template_id": "224744",
              "node_ids": [
                "end"
              ]
            }
          ]
        }
      ]
    }
  ]
}
```

### 拦截需求的草稿发布与创建

`1011` 为发布草稿，`1012` 为创建草稿，`story` 限定工作项类型。

```json
{
  "project_key": "{{project_key}}",
  "project_intercept_config": [
    {
      "events": [
        1011,
        1012
      ],
      "work_item_type": [
        "story"
      ]
    }
  ]
}
```

仅作用于模板 `224744`；不支持进一步限定到节点或子任务。此例再次表明 `template_ids` 的示例用法超出了参数表描述。

```json
  "project_intercept_config": [
    {
      "events": [
        1011,

        {
          "work_item_type": "story",
          "template_ids": [
            "224744"
          ]
        }
      ]
    }
  ]
}
```

## 错误码与排查

下列示例中 `err_code` 与 `err.code` 相同，`err_msg` 与 `err.msg` 相同，因此合并展示。

| 错误码 | 消息 | 排查方向 |
| --- | --- | --- |
| `20101` | `intercept config count overflow` | 配置数量超限；原文未给出数值上限 |
| `20102` | `intercept config marshal failed` | 入参无法反序列化 |
| `20103` | `intercept config json len overflow` | 单条配置长度超限；原文未给出数值上限 |
| `20006` | `Invalid Param` | 数据结构不匹配 |
| `20104` | `intercept config duplicated` | 同一工作项类型、同一事件类型出现重复配置 |
| `20105` | `intercept config scope overflow` | 工作项类型或事件超出开发者后台范围 |
| `20106` | `create intercept config failed` | 插件未添加拦截事件构成 |

更多错误见 [Open API 错误码](../formats/Open%20API%20错误码.md)。
