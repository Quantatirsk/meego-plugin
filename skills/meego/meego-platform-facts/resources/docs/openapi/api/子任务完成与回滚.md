# 子任务完成/回滚

<!-- capability-metadata:start -->
## 平台能力标记

<a id="capability-openapi.post.open-api-project-key-work-item-work-item-type-key-work-item-id-subtask-modify"></a>
- **子任务完成/回滚** ｜ `openapi.post.open-api-project-key-work-item-work-item-type-key-work-item-id-subtask-modify` ｜ 频次：低 ｜ 状态：待运行时验证

<!-- capability-metadata:end -->

将指定节点下的一个子任务标为完成，或回滚其完成状态。操作由 `action` 决定；可以在同一请求中提交负责人、排期、交付物和备注的更新。

## 完成与回滚的区别

| `action` | 作用 | 调用前检查 |
| --- | --- | --- |
| `confirm` | 完成子任务 | 子任务存在，必填交付物已填写，当前状态允许完成 |
| `rollback` | 回滚子任务 | 子任务与所属节点匹配，当前工作项允许操作 |

已完成任务重复确认可能返回 `50006 / Subtask already confirmed`。必填交付物缺失也可能返回 `50006`，需结合 `err.msg` 判断原因，不能只按顶层错误码分类。

负责人仍区分 `assignee` 与 `role_assignee`；排期参数在本接口定义为数组 `schedules`。产品操作见[任务管理](https://project.feishu.cn/1ykiuvvj/40gyakm8)与[完成任务](https://project.feishu.cn/1ykiuvvj/3bv61iew#%E5%AE%8C%E6%88%90%E4%BB%BB%E5%8A%A1)，插件权限见[权限管理](../guides/权限管理.md)中的“工作项实例”。

## 请求说明

**请求方式**：`POST`
**请求地址**：`/open_api/:project_key/work_item/:work_item_type_key/:work_item_id/subtask/modify`

### 路径参数

| 参数 | 类型 | 是否必须 | 说明 |

<a id="parameter-notes-1"></a>

**project_key 的填写说明**

空间 ID（project_key），或者空间域名（simple_name）。

- 空间 ID（project_key），在飞书项目空间双击空间名称获取。

- 空间域名（simple_name），`simple_name` 一般在飞书项目空间 URL 中获取。例如空间 URL 为 “https://project.feishu.cn/doc/overview”，则 `simple_name`为 “doc”。

<a id="Body"></a>

### 请求体

| 参数 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `node_id` | string | 必须 | 目标节点 ID（节点 ID 或节点 state_key、node_key 等价），可通过[获取工作流详情](获取工作流详情.md)接口获取。 |
| `task_id` | int64 | 必须 | 子任务的唯一标识 ID，通过[获取指定的子任务列表（跨空间）](获取指定的子任务列表（跨空间）.md)接口获取。 |

| `assignee` | `list<string>` | 可选 | 子任务负责人的 userkey 列表，当节点负责人类型为非角色负责人时可用。 |
| `role_assignee` | `list<object>` | 可选 | 子任务角色负责人列表，遵循[RoleOwner](../formats/数据结构汇总.md#3209a8ce)结构规范。当节点负责人类型为角色负责人时可用。<br>此字段为更新参数，可在完成或回滚操作的同时更新子任务字段。 |
| `schedules` | `list<object>` | 可选 | 估分排期信息，遵循[Schedule](../formats/数据结构汇总.md#8b67e4ee)结构规范。可在完成/回滚操作同时更新子任务字段 |
| `deliverable` | `list<object>` | 可选 | 交付物字段列表，用于在完成或回滚子任务操作时更新子任务的交付物信息。遵循[FieldValuePair](../formats/数据结构汇总.md#10c42182)结构规范 |
| `note` | string | 可选 | 备注信息，可在完成或回滚子任务操作的同时更新子任务的备注字段。 |

#### `schedules`

| 参数 | 类型 | 是否必须 | 说明 |

| `estimate_start_date` | int64 | 可选 | 排期开始时间戳，精度毫秒 |

| `is_auto` | boolean | 可选 | [填写说明](#parameter-notes-2) |
| `actual_work_time` | double | 可选 | 实际工时，精确到小数点后一位。该节点有填写实际工时才会返回，子任务不支持此参数 |

<a id="parameter-notes-2"></a>

**is_auto 的填写说明**

排期与估分更新模式，不传表示为 true

true：

- 若只填写了排期，则自动将估分补充为排期之间的差值

- 若只填写了估分，则会将排期清空

- 若排期、估分均填写，会按所填值落库

- 若排期、估分均未填写，则会将估分置为0、排期清空

false：

- 若只填写了排期，不会将估分补充为排期之间的差值

- 若只填写了估分，不会将排期清空

- 若排期、估分均填写，会按所填值落库

- 若排期、估分均未填写，则视为不做改动，而非清空

<a id="请求示例"></a>

## 请求示例

两个示例均执行 `rollback` 回滚。排期使用参数表定义的 `schedules` 数组，负责人由 `assignee` 或 `role_assignee` 指定。自定义字段另用[更新子任务](更新子任务.md)接口；`is_auto` 的默认值及省略行为见上方排期表。

**回滚子任务**

请求路径：`POST /open_api/64f7f57d89aa3bb71bfdxxxx/work_item/story/12584xxxx/subtask/modify`

```json
{
  "node_id": "initiate_review",
  "task_id": 6132974,
  "action": "rollback"
}
```

**回滚时更新子任务**

请求路径：`POST /open_api/64f7f57d89aa3bb71bfdxxxx/work_item/story/12584xxxx/subtask/modify`

```json
{
  "node_id": "initiate_review",
  "task_id": 6132974,
  "action": "rollback",
  "note": "chayihua",
  "role_assignee": [
    {
      "role": "RD",
      "owners": [
        "xxx"
      ]
    }
  ],
  "schedules": [{
    "points": 3,
    "estimate_start_date": 1724169600000,
    "estimate_end_date": 1724428799999
  }],
  "deliverable": [
    {
      "field_key": "field_123",
      "field_value": "test"
    }
  ]
}
```
