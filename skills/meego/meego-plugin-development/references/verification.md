# 验证路径

在新增非平凡行为、修复平台边界问题，或准备交付与发布时读取。验证要按层次区分，不能用一次构建替代所有检查。

| 层次 | 验证目标 | 适用检查 |
| --- | --- | --- |
| 契约 | 使用的点位、接口、事件和字段格式有来源 | 对照 `meego-platform-facts` 的已选资料与 fixture；不以真实凭证请求替代 fixture。 |
| 单元 | 本地转换和状态机正确 | 测试字段 metadata 到请求体的转换、上下文校验、取消、重复提交、超时和错误分支。 |
| 服务 | 自建后端在信任边界正确 | 测试 Pydantic 校验、授权/归属校验、header allowlist、超时映射、脱敏和幂等行为；替身上游服务，不调用真实 OpenAPI。 |
| 工程 | 源码可被目标工具链稳定处理 | 运行目标工程已有的类型检查、lint、测试和构建命令。没有测试工具时，为本次非平凡边界补最小且有意义的测试，不把 type-check 当作运行时验证。 |
| 宿主 | 每个声明点位能在真实环境工作 | 在网页端和已声明的移动端分别验证入口、JSSDK context、加载/失败态、写入或回调。 |
| 生命周期 | 产物和发布状态可追溯 | 通过 `meego-plugin-operations` 区分本地构建、上传、预览、发布、安装和发布后回归。 |

## 可复现构建

环境选择应来自受控配置或构建参数，不得用 `sed` 等方式修改受版本控制的常量。构建后检查工作树、产物内容和日志，确认其中没有密钥、token、授权码或环境专属凭证。

生产前还要确认服务端 CORS 不使用通配符、健康探针反映必要依赖、超时和错误路径可观察。把无法在当前环境完成的宿主或发布验证明确记录下来，而不是将其默认为通过。
