# 开发工作流

在 `meego resolve` 选出相关能力包后使用本参考。

## 建立工作契约

在实现计划或任务回复中记录：

- 所请求的结果和目标插件项目；
- 已解析的能力标识符及其验证状态；
- 用户或项目提供的业务事实；
- 已解析资料提供的平台事实；
- 仍然未知且阻碍决策的事实。

不得将示例中的标签、字段、数据模型、URL 或流程变成需求。只有已解析资料确立相关平台契约后，示例才能展示结构、生命周期处理或集成形态。

## 有目的地选择资料

每项能力使用一次聚焦的 `meego resolve` 查询。复合任务可能需要分别解析客户端点位、客户端 API、服务端操作和事件契约。

可用时按以下顺序阅读：

1. 选定能力的契约和状态；
2. 它的 schema 和 fixture；
3. 解析器指出的直接关联能力资料；
4. 仅在契约清晰后阅读实现示例。

已有经过整理的资料时，不得将原始抓取内容、生成索引或历史笔记视为规范。

仅当本地资料缺失、处于 `source_silent` 或 `needs_runtime_validation` 状态，或资料对时效敏感时，才使用 `lpm ai docs`。在将返回结果记录为补充证据前，确认其标题和官方 URL。没有明确且有证据支持的协调过程时，它不能替代缺失契约或覆盖选定的本地资料。

## 按边界实现

保持客户端、服务端和平台配置契约明确。

- 客户端入口只使用其选定点位支持的能力和上下文。
- 服务端集成可按已解析的 OpenAPI 请求、认证、响应、重试和事件契约实现运行时 HTTP 客户端。秘密信息保留在其运行环境中，绝不放进客户端代码或示例。
- 配置只使用已解析 schema 和当前远端基线支持的字段和值。

某项能力需要运行时验证时，添加聚焦的手动或自动检查，在目标宿主环境中证明未解决的行为。将其表述为验证，不要表述为已记录的保证。

## 远端操作前验证

运行覆盖该变更的目标项目本地检查。确认代码、配置草案和示例不含凭据值或编造的业务数据。任何平台变更随后均遵循[远端操作](remote-operations.md)。
